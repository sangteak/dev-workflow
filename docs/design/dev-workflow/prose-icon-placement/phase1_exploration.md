- `action: spec-change`
- 근거: 언어 규범 펜스와 plan-stage 템플릿이 이미 있고, 이번 일은 그 요구 사항(설명 문장 안의 아이콘 허용 여부, 사실 여럿일 때의 모양, 판정 표기)을 바꾸는 것이다. 겉모양이 달라지므로 리팩터링이 아니고, 규범이 멈춘 것이 아니라 정한 대로 동작한 결과라 결함 수정이 아니다.

## 종료 조건 충족 내역 (spec-change: 「무엇이 어떻게 바뀌는가」)

무엇이: 아이콘이 화면에서 차지하는 자리의 규칙, plan-stage의 Feasibility 판정 출력과 Researcher 조사 결과 템플릿, 워커 프롬프트의 언어 규범 구획, 사후 검사 스크립트.

어떻게:
- 아이콘은 줄 첫머리와 이름표에만 쓴다. 이름표(`✔️ 확인된 사실:`), 불릿 머리(`- ✔️`), 판정 이름표(`⚠️ CAUTION`)가 그 자리다. 개행이나 콜론 뒤의 설명 문장 안에서는 아이콘으로 낱말을 대신하지 않는다. 판별은 아이콘 바로 뒤에 조사가 붙었는지로 한다 — "⚠️를 유지하면"이 아니라 "주의 판정을 유지하면"
- 판정은 아이콘과 낱말을 함께 쓴다 — `⚠️ CAUTION`. 종합 판정 줄의 아이콘 슬래시 나열(`✅ / ⚠️ / 🚫`)도 낱말 병기로 고친다
- Feasibility 판정 발언을 한 모양으로 합친다 — 페르소나 이름 줄에 판정 아이콘과 낱말, 개행 뒤 근거 한두 문장(아이콘 없음). 로컬 정형과 생산 규격을 따로 싣고 우선 관계를 글로 조정하던 것을 그만둔다
- Researcher 조사 결과 템플릿의 확인된 사실 칸만 이름표 뒤 개행과 불릿으로 내린다. 우회 가능성과 유사 패턴은 한 줄 정형 유지
- 워커 프롬프트의 언어 규범 구획 머리에 "앞 화면의 모양이 아니라 이 구획의 규범을 따른다" 한 줄을 둔다
- 상시 주입본 요약 줄에 아이콘 자리 조항을 약 30자 더한다
- 사후 검사 `scripts/transcript-sources.mjs`에 아이콘 뒤 조사가 붙은 줄과 같은 이름표가 되풀이된 화면을 세는 패턴을 더하고 종료 코드에 넣는다

## 탐색된 요구사항 전체 목록

1. 언어 규범 펜스에 아이콘 자리 규칙 문장 (줄 첫머리와 이름표에만, 설명 문장 안 낱말 대체 금지, 조사 판별)
2. 상시 주입본 요약 줄에 아이콘 자리 조항 추가
3. 워커 프롬프트 언어 규범 구획 머리에 앞 화면 모양을 따르지 않는다는 한 줄
4. 판정 표기에 아이콘과 낱말 병기, 종합 판정 줄의 슬래시 나열 정리
5. Feasibility 판정 발언을 한 모양으로 합침 (이름 줄에 판정, 개행 뒤 근거 한두 문장)
6. Researcher 조사 결과 템플릿의 확인된 사실 칸을 이름표 뒤 개행과 불릿으로
7. 사후 검사에 조사 붙은 아이콘과 이름표 되풀이 패턴, 종료 코드 포함
8. 잔존 검사와 도착 검사
9. 실사용 확인 — 새 세션과 이어 쓰기 세션 둘 다
10. 릴리스 버전 올리기

## 사용자가 명시적으로 제외한 항목과 이유

- ⚠️(확인 못 함)와 ⚠️ CAUTION의 두 뜻 겹침을 푸는 것 — 낱말 병기로 읽는 쪽 문제가 사라지므로 이번 범위 밖
- 제목, 항목 머리, 판정 이름표, 확인 아이콘 자리의 아이콘을 줄이는 것 — 구분에 유용하다는 사용자 판단
- 확인 아이콘의 뜻, 근거 첨부 의무, 증거 구획 구조 변경
- 1.28.0이 걷어낸 출처 문자열과 인용을 되돌리는 것
- Feasibility 판정 기준 자체(FEASIBLE, CAUTION, RENEGOTIATE) 변경
- 결정 박스 설명 블록에 분량 상한을 두는 것 — 규범이 상한을 두지 않는다고 못 박고 있고, 증상은 길이가 아니라 아이콘 대체에서 왔다

## 페르소나 피드백 결과

- 라운드 1 (블라인드): 합의 넷 — 언어 규범 문장 추가, 판정 아이콘과 낱말 병기, 조사 결과 템플릿의 확인된 사실 칸만 불릿으로, Feasibility 판정 프롬프트의 두 정형 합치기. 미합의 둘 — 컨텍스트 오염 대응과 사후 검사 확장
- 사용자 결정: 컨텍스트 오염은 워커 프롬프트 구획 머리 한 줄(1번), 사후 검사는 조사 붙은 것만 세고 종료 코드 포함(1번)
- 본체가 보탠 사실: plan-stage 판정 출력 형식의 종합 판정 줄이 `→ 종합 판정: ✅ / ⚠️ / 🚫`로 아이콘만 쓰고 슬래시로 잇는다 — 낱말 병기와 슬래시 금지 둘 다에 걸려 같이 고칠 자리
- 두 페르소나의 전제 반박이 같은 방향: 원인이 컨텍스트 오염이 아니라 판정 프롬프트 충돌이면 훅과 고지 보강은 헛발이다. 새 세션 한 바퀴로 먼저 갈라야 한다

## 인터뷰 결과 (Step A)

- 질문 1 (아이콘 거부의 범위): 제목과 항목의 아이콘 강조는 유지, 설명 안에서 낱말을 대신하는 것만 금지. 사용자 원문 — "제목 등 항목은 아이콘으로 강조하는것이 바람직하다고 생각하고, 실제로 구분에 유용해. 다만 설명에 아이콘으로 대체하니 글을 읽을 때 생각을 해야 하는 상황이 생겨서 자연스럽게 읽히지 않아."
- 질문 2 (완료 기준): 읽을 때 막힘이 없는 것. 사용자 원문 — "설명은 불필요한 첨부 내용이나 무분별한 아이콘 사용으로 글을 읽는데 방해가 안되게 됐으면해. 즉, 가독성을 올려줘." 사용자 눈이 최종, 스크립트는 문지기
- 질문 3 (옛 태그 재발 원인): 이어 쓰던 세션에서 플러그인만 올리고 재시작한 뒤의 화면 — 컨텍스트 오염이 유력. 옛 화면이 있어도 새 규범이 이기는 것이 요구사항
- 질문 4 (화면의 경계): 메인 세션이 직접 쓰는 화면도 대상. 규칙은 언어 규범 자리. 되물음 한 번(낱말 풀이 — "본체"가 무엇인지) 뒤 사용자가 추천 이유를 묻고 1번 승인
- 질문 5 (이름표 되풀이의 뿌리): 템플릿 모양. 여럿일 때의 모양을 템플릿에 정한다
