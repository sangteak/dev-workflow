# prose-icon-placement 설계 문서

> 한 줄 요약: 아이콘을 줄 첫머리의 강조로만 남기고 설명 문장 안에서 낱말을 대신하지 못하게 한다 — 1.28.0이 출처 문자열을 걷어낸 자리를 아이콘과 이름표 되풀이가 채워 같은 읽기 부담이 남았다.

## 1. 배경과 동기

1.28.0(grounded-output-display)은 화면 본문에서 출처 문자열과 인용을 걷어내고 확인 아이콘만 남겼다. 그 뒤 소비 프로젝트의 PLAN 화면에서 증상 셋이 나왔다. 첫째, Feasibility 판정 페르소나 발언이 옛 대괄호 태그를 그대로 달고 문단이 대여섯 문장이었다. 둘째, 조사 결과 화면이 사실마다 이름표를 되풀이해 네 줄이 모두 같은 말로 시작했다. 셋째, 결정 박스 산문이 낱말 대신 아이콘을 썼다 — "REQ-006에 ⚠️를 준 이유", "✅로 올리면".

사용자의 말이 문제를 정확히 짚는다. "제목 등 항목은 아이콘으로 강조하는 것이 바람직하고 실제로 구분에 유용하다. 다만 설명에 아이콘으로 대체하니 글을 읽을 때 생각을 해야 하는 상황이 생겨 자연스럽게 읽히지 않는다." 그리고 "이전 작업의 목표는 설명을 읽을 때 막힘없이 읽히길 원했던 것인데, 이 아이콘 또한 과하게 쓰이다 보니 같은 문제가 있다."

즉 1.28.0이 고친 것은 첨부물이었고 남은 것은 표시 자체의 과잉이다. 설치된 1.28.0 사본에는 옛 대괄호 모양이 없으므로 워커가 규범에서 베낀 것은 아니다.

## 2. 목표와 비목표

### 목표

- GOAL-001: 설명 문장 안에서 아이콘이 낱말을 대신하지 않는다. 판정은 낱말로 부르고 확인 상태도 낱말로 쓴다
- GOAL-002: 제목, 항목 머리, 판정 이름표, 확인 아이콘 자리의 아이콘은 그대로 남아 화면 구성이 한눈에 보인다
- GOAL-003: 조사 결과 화면에서 이름표가 항목당 한 번만 나온다
- GOAL-004: 이어 쓰던 세션에 옛 화면이 남아 있어도 새 규범이 이긴다

### 비목표

- 확인 아이콘과 판정 아이콘의 뜻 겹침을 푸는 것 — 낱말 병기로 읽는 쪽 문제가 사라진다
- 제목, 항목 머리, 판정 이름표, 확인 아이콘 자리의 아이콘을 줄이는 것
- 확인 아이콘의 뜻, 근거 첨부 의무, 증거 구획 구조를 바꾸는 것
- 1.28.0이 걷어낸 출처 문자열과 인용을 되돌리는 것
- Feasibility 판정 기준 자체를 바꾸는 것
- 결정 박스 설명 블록에 분량 상한을 두는 것 — 규범이 상한을 두지 않는다고 못 박고 있고 증상은 길이가 아니라 아이콘 대체에서 왔다
- 판정 발언을 두 줄로 나누는 것 — 화면이 40퍼센트 길어져 목표와 반대 방향
- 상시 주입본 요약 줄에 아이콘 조항을 더하는 것 — 규범 정본을 읽으라는 지시가 이미 있어 후속으로 미룸

## 3. 확정된 요구사항

- REQ-001: 언어 규범 펜스에 아이콘 자리 규칙을 넣는다. 아이콘은 줄 첫머리(이름표, 불릿 머리, 판정 이름표)에서 맨몸으로 쓰고, 그 자리를 벗어나 문장 속에서 아이콘 자체를 가리킬 때는 백틱으로 감싼다. 백틱 없는 맨몸 아이콘이 문장 중간에서 조사를 달고 낱말 자리를 차지하면 낱말 대체이고 금지한다. 낱말과 괄호로 병기한 자리(`확인 아이콘(✔️)이`, `가운뎃점(·)을`)는 낱말이 앞에 있어 대상이 아니다 — 이 경계를 규칙 문장에 함께 적는다 — 우선순위: HIGH
- REQ-002: 같은 펜스의 첫 문장 바로 다음에 "앞 화면의 모양이 아니라 이 구획의 규범을 따른다" 한 줄을 둔다. 조립된 워커 프롬프트에서도 구획 머리에 오게 한다 — 우선순위: HIGH
- REQ-003: 판정 표기에 아이콘과 낱말을 함께 쓴다. plan-stage의 종합 판정 줄 `→ 종합 판정: ✅ / ⚠️ / 🚫`를 낱말 병기로 고친다. 판정 요약 칸은 이미 병기되어 있어 손대지 않는다 — 우선순위: HIGH
- REQ-004: Feasibility 판정 발언은 한 줄을 유지하고 낱말 병기와 대괄호 태그 제거만 한다 — `🔧 TD: ✅ FEASIBLE — 기존 큐 설정으로 처리 가능` 모양. 줄을 나누지 않는다 — 우선순위: HIGH
- REQ-005: Researcher 조사 결과 템플릿의 확인된 사실 칸만 이름표 뒤 개행과 불릿으로 내린다. 불릿에는 아이콘을 붙이지 않는다고 템플릿에 명시한다. 우회 가능성과 유사 패턴과 결론은 한 줄 정형을 유지한다 — 우선순위: HIGH
- REQ-006: 저장소에서 아이콘이 홀로 선 자리(낱말 병기 없이 조사가 바로 붙은 자리)에 백틱을 씌우거나 낱말로 바꾼다. 실측은 12건 9행 3파일이다 — 규범 정본, 실물 문구와 brainstorming 스킬. 괄호 병기 자리는 대상이 아니다. 고지 문구는 중첩 백틱을 피하려고 낱말 병기로 다시 쓴다. 규범 정본은 자기 규칙을 어기지 않아야 하므로 REQ-001과 같은 커밋에 묶는다 — 우선순위: HIGH
- REQ-007: `tests/hooks/test-restatements.sh`의 도착 검사가 규범 정본의 "확인 아이콘(✔️)이 한 줄도 없으면"을 리터럴로 대조한다. 그 자리는 괄호 병기라 이번 스윕 대상이 아니므로 검사는 그대로 통과해야 한다 — 스윕 뒤 이 검사가 여전히 통과하는지 확인한다. 같은 행의 다른 아이콘(이름표의 ✔️로 센다)은 홀로 선 자리라 대상이다 — 우선순위: HIGH
- REQ-008: 사후 검사 `scripts/transcript-sources.mjs`에 백틱 없는 맨몸 아이콘에 조사가 붙은 패턴을 더하고 종료 코드에 넣는다. 이름표 되풀이 패턴도 더하되 종료 코드에는 넣지 않고 숫자만 보고한다 — 항목 경계를 빈 줄로 잡는 근사치라 첫 실사용에서 오탐 표본을 모은다. 판정 기준은 이름표 직후 불릿에 같은 아이콘이 한 번이라도 다시 붙으면 위반이다. 검사 대상은 세션 기록이고 저장소 규범 문서는 아니다 — 우선순위: HIGH
- REQ-009: 잔존 검사와 도착 검사를 test-restatements.sh에 더한다 — 새 규범 문장의 도착과 옛 모양의 잔존. REQ-006과 같은 패스에서 처리한다 — 우선순위: HIGH
- REQ-010: 실사용 확인 — 새 세션과 이어 쓰기 세션 둘 다. 새 세션에서는 첫 고지의 아이콘이 백틱으로 감싸져 있는지 보고, 이어 쓰기 세션에서는 판정 화면과 조사 결과 화면이 새 모양으로 나오는지 본다. 주의 판정이 나올 요구사항을 의도적으로 넣어 판정 화면과 조사 화면을 만든다. 백틱이 터미널에서 어떻게 보이는지도 이때 확인한다 — 우선순위: HIGH
- REQ-011: 릴리스는 PATCH 1.28.1 — 1.28.0이 아직 원격에 없고 실사용 확인도 통과하지 못한 상태라 이번 작업이 그 릴리스의 목표를 마저 채운다. `scripts/bump-version`으로 두 파일 동기 — 우선순위: MEDIUM

## 4. 설계 개요

고칠 자리는 세 층이다.

규범 층은 언어 규범 펜스 하나다. 아이콘 자리 규칙과 앞 화면을 따르지 않는다는 한 줄이 여기 들어가고, 이 펜스는 실행 시점에 워커 프롬프트로 복제되므로 별도 전파 작업이 없다. 규범 정본 자신이 백틱 대상 여섯 행을 갖고 있어 규칙과 스윕을 같은 커밋에 묶는다.

템플릿 층은 plan-stage 하나다. 종합 판정 줄의 낱말 병기, 판정 발언의 태그 제거, 조사 결과 템플릿의 확인된 사실 칸이 모두 같은 파일에 있고 일부는 같은 열다섯 줄 블록이라 한 패스에서 처리한다.

검사 층은 둘이다. 사후 검사는 세션 기록에서 백틱 없는 맨몸 아이콘에 조사가 붙은 줄을 세어 종료 코드에 넣고, 이름표 되풀이는 숫자만 보고한다. 잔존과 도착 검사는 저장소 파일에서 새 문구의 도착과 옛 모양의 잔존을 센다. 도착 검사가 규범 정본의 한 문자열을 리터럴로 대조하고 있어 백틱 스윕과 같은 커밋에서 고쳐야 조용히 깨지지 않는다.

## 7. 제약조건과 가정

규칙은 언어 규범 펜스에 둔다. 이 펜스는 모든 사용자 대면 문면에 적용되고 워커 프롬프트에 실행 시점으로 복제되므로 문서 사본을 만들지 않는다. 상시 주입본은 이번에 늘리지 않는다. 판정 이름표와 확인 아이콘의 뜻과 자리는 그대로 두고, 검증 규범의 이름표 문장도 고치지 않는다. 도메인 문서와 feature 문서 평문에 불릿을 쓰지 않는다. 커밋과 푸시는 마무리 절차에서만 하고 버전은 스크립트로만 올린다.

가정은 셋이다. 옛 태그 재발의 주된 원인은 이어 쓰던 세션에 남은 옛 화면이다. 언어 규범 펜스의 규칙은 상시 주입본 요약과 워커 복제로 전파된다. 실사용 확인은 사용자가 수행한다.

저비용 판단이 "언어 규범 펜스는 실행 시점 복제이지 문서 사본이 아니다"라는 단일 원본 구조에 기댄다. 펜스를 문서로 박아 넣는 파일이 새로 생기면 비용 추정이 올라간다. 백틱이 터미널에서 어떻게 보이는지는 실측하지 않았고 실사용 확인에서 눈으로 본다.

## 8. 기술 가이드라인

- REQ-001과 REQ-006을 같은 커밋에 묶는다 — 규범 정본 자신이 백틱 대상을 갖고 있어 규칙만 넣으면 바로 아래 문단이 자기모순이 된다
- REQ-006과 REQ-007을 같은 커밋에서 처리한다 — 도착 검사가 규범 문자열을 리터럴로 대조하므로 따로 가면 검사가 조용히 깨진다
- 백틱 대상은 실측 12건 9행 3파일이고 구현 시작 때 다시 센다 — 판별은 아이콘 바로 앞이 백틱이나 여는 괄호가 아니고 뒤에 조사가 바로 붙은 자리다
- 펜스 내용을 손으로 옮겨 적은 요약 사본 네 곳(상시 주입본, orchestrator 스킬 둘, brainstorming 스킬)을 눈으로 한 번 더 본다 — 상시 주입본은 비목표라 고치지 않고 나머지 셋에 홀로 선 아이콘이 있는지만 확인한다
- 실사용 확인의 판정 범위는 증상 셋의 해소 여부다. 미푸시 릴리스 여섯을 한꺼번에 판정하는 구조는 그대로지만, 실패하면 어느 릴리스 탓인지 가리기 어렵다는 점을 실사용 표에 적어 둔다
- REQ-002의 한 줄은 펜스 첫 문장 바로 다음에 둔다 — 중간에 넣으면 조립된 프롬프트에서 구획 머리가 아니게 된다
- REQ-003과 REQ-004는 plan-stage의 같은 블록을 건드리므로 한 패스에서 처리한다
- REQ-005의 템플릿에 "불릿에는 아이콘 없이"를 명시한다 — 안 적으면 그 산출물이 되풀이 검사의 위반을 스스로 만든다
- REQ-005를 먼저 고치고 그 산출물로 REQ-008의 정규식을 실측 검증한다
- REQ-008의 판정 로직은 빈 줄과 새 이름표로 상태를 리셋하고 이름표 직후 불릿에 같은 아이콘이 붙으면 표시한다
- REQ-010에서 주의 판정이 나올 요구사항을 의도적으로 넣는다 — 자연 발생을 기다리면 판정 화면과 조사 화면을 못 볼 수 있다
- 범례처럼 아이콘과 낱말 사이에 공백이 있는 자리는 조사 판별에 걸리지 않는다 — 공백 유무가 이름표와 낱말 대체를 가르는 실제 경계선이다

## 9. 구현 결과 및 일탈 사항

개발 세션 잡음 실측: REQ-008 사후 검사(`scripts/transcript-sources.mjs`)를 이 기능을 개발한 세션 자신의 transcript에 돌리면(리뷰 Fix Round 1 반영 후 재실측) `--- assistant 줄 17477, main 위반 1035 (옛 태그 636, 경로:행 322, 인용 38, 홀로 선 아이콘 39), 이름표 되풀이 0(보고만), worker 위반 1326(보고만), 제외 줄 2096, 출처 218개 파일` 로 나오는데, 이 저장소 자신을 고치는 개발 세션은 파일 경로 언급이 정당한 작업 내용이라 위반 다수가 정상이며 통과 기준은 소비 프로젝트의 브레인스토밍 한 바퀴다.

잔존 검사 실측: `tests/hooks/test-restatements.sh`의 `residue` 헬퍼는 룩비하인드를 못 쓰므로 홀로 선 아이콘을 백틱과 여는 괄호를 제외한 문자 클래스(`bareicon`)로 근사했다. 이 패턴이 실제로 뭔가를 잡는지 먼저 임시 파일로 증명했다 — 홀로 선 아이콘 줄 하나와 백틱으로 감싼 줄, 괄호로 병기한 줄을 섞은 표본에 같은 `grep -cE` 명령을 돌리면 홀로 선 줄 하나만 걸리고 나머지 둘은 면제됐다. 이 패턴을 저장소 대상 파일 넷(decision-flow.md, grounding.md, brainstorming/SKILL.md, plan-stage/SKILL.md)에 돌리자 grounding.md 7행의 세션 최초 고지 문구에서 "확인 아이콘 ✔️는"과 "확인 못 함 ⚠️는"이 걸렸다. 이 줄은 문장 전체가 백틱 하나로 감싸여 있어 아이콘 바로 앞 글자가 백틱이 아니라 공백이었고, 그래서 면제되지 않고 걸렸다. "확인 아이콘(✔️)은", "확인 못 함(⚠️)은"으로 괄호 병기해 고치자 저장소 대상 파일 넷 모두 0건이 됐다. 괄호 병기로 바꾸면 조사가 아이콘이 아니라 앞 낱말에 붙으므로 받침에 맞춰 "는"이 아니라 "은"을 쓴다 — 처음 고칠 때 조사를 그대로 두어 어색한 문장이 됐고 뒤이어 바로잡았다.

| 확인 항목 | 판정 방법 | 결과 |

| 조사 결과 화면에서 확인된 사실 이름표가 항목당 한 번만 나온다 | 눈 | 미완료 |
