### 2. `decision-flow.md:440` — 기본값 뒤집기

### 3. 「답의 후보」 칸 — `templates.md`

역할 정의 블록이 아니라 그것을 감싸는 프롬프트의 반환 지시에 넣는다. `agent-roles.md`는 첫 줄에 "문장 수정 금지"가 박혀 있고, 그 안의 Socratic 정의가 "반드시 질문으로 끝내라"를 요구하므로 칸을 질문 **앞**에 둔다.

Ontologist 프롬프트와 Socratic 프롬프트 끝에 붙일 문장:
> 질문마다 「답의 후보」를 **먼저** 줄 단위로 적고 그다음 질문 본문을 쓴다. 후보가 한 줄도 안 적히면 「답의 후보: 없음」이라고 적는다.

반환 형식:
```
답의 후보:
- [후보]
- [후보]

질문: [질문 본문]
```

## 국면 2 결정 사항

### 4. `design-summary` 범위 질문 화면 — 카테고리를 센다

세 갈래로 동작한다.

- 카테고리 0개 → "설계 문서를 찾지 못했습니다"로 끝낸다. 질문 자체가 없다
- 카테고리 1개 → 묻지 않고 그 카테고리 전체를 범위로 잡아 한 줄 고지한 뒤 매칭 결과 확인으로 넘어간다
- 카테고리 2개 이상 → 번호 목록으로 묻는다

근거: 매칭 결과 확인 화면이 이미 문서 목록을 번호로 내고 "이 문서들의 통합 요약을 생성할까요?"로 확인받으므로, 범위 질문에서 문서까지 고르게 하면 같은 목록을 두 번 보게 된다. 카테고리가 하나뿐일 때 안 묻고 넘어가는 것은 이 저장소가 다른 자리에서도 쓰는 축약이다.

이 저장소는 카테고리가 `dev-workflow` 하나라 실제로는 화면이 안 뜬다.

### 7. 실물 재현의 자리 — main 머지 뒤 새 세션

마켓플레이스가 `D:\02_Workspace\98_Github\dev-workflow`를 직접 가리키는 구조라 머지 없이는 새 문면이 안 보인다. 그래서 커밋과 머지가 재현보다 앞서고, 재현에서 문제가 나오면 후속 커밋으로 고친다.

물리친 대안:
- 마켓플레이스에 워크트리 경로를 임시로 더하기 — 설정을 바꿨다 되돌리는 일이 늘고, 되돌리기를 빠뜨리면 다음 세션이 워크트리 버전을 문다
- `D:\` 체크아웃에서 브랜치를 잠깐 바꾸기 — `main` 작업 트리를 건드린다. 이 저장소는 그 오염을 네 번 겪었다

기록 자리: 재현 결과 한 줄을 `[기능명].md`의 9번 절 「구현 결과 및 일탈 사항」에 적는다. 그 절이 이름 그대로 구현 결과를 담는 자리이고, 설계 문서는 도메인 머지 전까지 살아 있다. `tasks/lessons.md`에는 성공 기준 6번대로 재발 원인과 남는 한계를 적는다.
