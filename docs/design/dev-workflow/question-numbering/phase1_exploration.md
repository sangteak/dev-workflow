### 전제 반박

- 🎯 — 시드가 "본체가 직접 쓴 개방형 질문은 흔적이 안 남는다"를 본체 경로에만 걸린 한계로 잡았으나, 페르소나 경로에도 똑같이 걸린다. 후보가 한 줄 이하로 나와 개방형이 되면 칸이 화면에 안 올라가므로 실제로 적어 봤는지가 남지 않는다. 무너지는 것은 재발 감지 수단이다
- 🛠️ — 반증된 것은 처방 형태가 아니라 조건부 술어일 수 있다. `decision-flow.md`의 같은 처방 형태 셋 중 이번에 안 지켜진 것만 조건부 술어를 쓴다. 처방 형태가 무효라면 실효를 남기는 유일한 조항이 기본값 뒤집기이므로, 술어 교체가 보조가 되고 기본값 뒤집기가 본체가 된다. 그리고 통과 선언의 근거가 문서 스윕에서 실물 화면 재현으로 바뀐다

## 시드 (Step B 사용자 확인 완료)

**Goal**
질문을 내보내기 전에 세는 술어를 「답의 후보를 셀 수 있는가」에서 「답의 후보를 적어 본다」로 바꾸고, 개방형 기본값과 검사 면제가 서로를 면제하던 두 조항을 함께 고쳐, 답의 후보가 닫힌 질문이 번호 선택지 없이 나가는 재발을 막는다.

**Constraints**
- 범위는 질문 트랙만
- 세는 단계는 조건 없이 항상 돈다 — 먼저 통과해야 할 판단 관문을 두지 않는다
- 조항 수를 늘리지 않는다 — 있는 문장 둘을 고쳐 쓴다
- 규범을 고치면 재서술 지점 목록에 따라 복제된 자리를 같은 차례에 고친다
- 훅이나 MCP 도구로 강제하지 않는다
- 커밋 전 사용자 확인

**Non-goals**
- 판정한 흔적이 안 남는 다른 판정 단계 전반
- 질문 문장의 어미를 보는 검사
- 개방형으로 나가는 질문에 근거 줄 붙이기
- 원본만 남기고 복제를 원본 가리키는 한 줄로 줄이는 정리
- 결정과 질문의 화면 형식 통합

**Success Criteria**
1. 세는 술어가 행위 지시로 바뀌고, 옛 술어가 `skills/` 아래에서 0건
2. 440번째 줄 기본값이 뒤집히고 427번째 줄 면제 조건이 "후보를 적어 본 결과가 하나 이하"로 좁혀짐 — 조항 수 불변
3. 페르소나 반환 형식에 「답의 후보」 칸이 생기고, 본체가 직접 세는 조건이 규범에 적힘
4. 산문으로 박힌 닫힌 질문 다섯 자리가 번호 선택지 화면으로 바뀜
5. `scripts/bump-version --check` 통과, `tests/hooks/run-all.sh` 회귀 없음
6. 재발 원인과 남는 한계가 `tasks/lessons.md`에 기록됨
7. **질문 트랙 한 자리를 실제로 돌려 닫힌 질문에 번호가 붙는 것을 확인** — 그 인터뷰의 질문마다 번호 유무를 세어 기록으로 남긴다 (국면 1 결정 5·6에서 추가)
8. **도메인 문서 두 파일의 v1.25.0 딱지 열다섯 곳이 실제 번호로 바뀜** (국면 1 결정 7에서 추가)

**Assumptions**
- 「세는 단계를 경로에 박으면 지켜진다」는 처방 형태가 유효하다 — 한 번 반증됐고, 이번엔 술어를 바꿔 다시 건다
- 본체가 직접 쓴 개방형 질문은 후보를 적어 봤는지가 화면에 안 남는다. 라운드에서 이 한계가 페르소나 경로에도 똑같이 걸린다는 지적이 나왔고, 대기열 기각으로 그대로 받아들이기로 했다
- 규범 준수를 검사하는 자동 장치는 이번에도 만들지 않는다

**Open Questions (국면 1에서 전부 해소)**
