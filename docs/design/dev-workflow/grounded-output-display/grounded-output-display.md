# grounded-output-display 설계 문서

> 한 줄 요약: 검증 규범이 화면 본문 줄마다 붙이던 출처 문자열과 원문 인용을 걷어내고 확인 아이콘만 남긴다 — 검증 장치는 그대로 두고, 근거는 워커 반환물의 증거 층에 두었다가 사용자가 요청할 때만 펼친다.

## 1. 배경과 동기

검증 규범(grounded-output v1.21.0)은 모델이 확인 없이 단정하는 것을 막으려고 화면의 모든 주장 앞에 전치 태그와 증거를 붙이게 했다. 그 결과 GW-Server 브레인스토밍의 조사 답변은 거의 모든 불릿이 `[✔ open-match v1.8.1 backend_service.go:212, clientcache.go:41-56]`, `[✔ kubernetes.io Service API publishNotReadyAddresses "This field defaults to false"]` 같은 태그, 출처 문자열과 영문 인용문으로 시작했고, 사용자는 "가독성이 너무 떨어져서 이슈 파악이 힘들다"고 했다. 본체가 출처를 전부 뺀 판을 다시 써 주자 잘 읽혔고, 그 다시 쓰기는 토큰과 시간을 한 번 더 썼다.

사용자의 결론은 "파일과 행 번호가 정말 필요한가, 확인된 사실이 무엇인지가 중요하고 상세는 필요한 시점에 물어보면 된다"였다. 검증 자체(추론을 줄이는 장치)는 유지하되, 그 근거가 화면에 오르는 자리를 바꾸는 것이 이 기능이다.

## 2. 목표와 비목표

### 목표

- GOAL-001: 조사 답변, 결정 박스, 페르소나 발언의 본문 줄에서 출처 문자열(프로젝트 이름, 버전, 파일 경로, 행 번호, 출처 주소)과 따옴표 원문 인용이 사라지고 확인 아이콘과 사실만 남는다
- GOAL-002: 검증 장치(워커의 근거 첨부, 본체 관문 대조, 증거 없는 주장의 강등, 반증 주석)는 화면 표시가 바뀐 뒤에도 그대로 동작한다
- GOAL-003: 사용자가 자연어로 요청하면 그 줄의 근거를 별 메시지로 펼치고, 증거가 컨텍스트에 없으면 재확인해 새 근거임을 밝힌다
- GOAL-004: 재발은 규범 문구와 세션 기록 사후 검사 스크립트로 잡는다

### 비목표

- 검증 규범 자체(출처 3종, 태그 넷의 뜻, 본체 관문)를 없애거나 다시 설계하는 것
- 페르소나 발언의 정형(결론 1줄, 근거 3개 이내, 전제 반박 1개)을 바꾸는 것
- 실행 시점에 화면을 검사하는 자동 검사기 — 도메인 문서의 기존 결정과 충돌하고 훅은 답변 본문을 화면 전에 고칠 수 없다
- 본체가 매번 다시 쓰는 방식 — 비용이 이중으로 들고 원문 전달 원칙과 부딪힌다
- 답변 끝 확인 건수 한 줄 — 줄마다 확인 아이콘이 남기로 한 뒤에는 겹치는 표시 (Simplifier 제안 수용)
- 사실 줄에 번호 매기기 — 결정 박스의 번호는 선택지 몫
- 증거 층을 phase 파일이나 HANDOFF에 저장하는 것 — 불변 스냅샷에 경로와 인용이 번지고, HANDOFF는 save부터 resume 사이만 지킨다
- 소비자 피드백 루프(관측 파일) — grounded-output 후속으로 따로 분리돼 있음
- 다른 프로젝트(GW-Server)의 표본 답변을 직접 고치는 것

## 3. 확정된 요구사항

- REQ-001: 화면 본문 줄에서 출처 문자열과 원문 인용을 뺀다. 범위는 화면에 오르는 문면 전부 — 조사 답변, 결정 박스의 「확인된 사실」과 「확인 못 한 것」 칸, 판정형과 지도형의 근거 줄, 페르소나 발언. 예외: 출처가 고칠 위치를 가리키는 자리(마무리의 대조 화면 `↳ ✔️ 10절 [날짜] 행 — …`)는 위치를 남기고 모양만 바꾼다. 구현 때 판정형 자리 다섯을 대조해 같은 성격의 자리를 예외 목록에 적는다 — 우선순위: HIGH
- REQ-002: 확인 여부 아이콘은 확인된 사실 ✔️(U+2714 U+FE0F 이모지 표현), 확인 못 한 것 ⚠️. 대괄호 없음. 이름표가 없는 자리(조사 답변, 페르소나 발언의 근거 불릿)는 줄마다, 이름표가 있는 자리(`✔️ 확인된 사실:`, `⚠️ 확인 못 한 것:`, `✔️ [판정]로 본 이유:`)는 이름표에 한 번만 붙이고 아래 줄에는 되풀이하지 않는다. 판정형 근거 줄에도 이름표를 두어 지도형과 같은 모양으로 맞춘다. 확정과 완료 줄의 ✅는 그대로 — 우선순위: HIGH
- REQ-003: 추측은 화면 층에서 ⚠️로, 반증은 `↳ ✘ 반증 — …`로 쓴다(대괄호 없음). 세션 첫 고지 문구는 짧게 다시 쓰고 펼치기 부르는 법을 넣는다. 실물: `ℹ️ 표시 안내: ✔️는 셈이나 저장소나 공식 문서로 확인한 사실, ⚠️는 확인 못 해 판단이 필요한 것입니다. 근거는 "출처 보여줘"로 펼칩니다.` — 우선순위: HIGH
- REQ-004: 워커(페르소나, 조사 워커) 반환물을 `--- 화면 ---`과 `--- 증거 ---` 두 구획으로 나눈다. 화면 층 근거 불릿은 `- ✔️ 주장 1줄`이고 대상 이름을 문장 안에 넣는다. 증거 층은 번호 목록이고 항목 첫머리에 화면 줄을 그대로 반복한 뒤 `↳ 경로:행 — "인용 1줄"`(외부는 `↳ 주소 — "인용"`, 계산은 `↳ 셈 — 식`)을 잇는다. 짝은 순서를 기본으로 하고 어긋나면 문자열로 찾는다. 사본이 다르면 화면 층이 정본이고 그 항목만 확인 불가로 강등한다. 확인 아이콘 셈 대상은 근거 불릿만이고 결론 줄과 전제 반박 줄은 증거 없음이 정상이다. 화면 층을 만드는 경로 여섯(페르소나 워커, Feasibility 판정 워커, plan-stage Researcher와 Architect 워커, 외부 문서 조사 워커, 미답변 조사 워커, 본체 직접 작성)에 모두 같은 두 구획을 쓰고 새 규격은 만들지 않는다 — 외부 문서 조사 워커의 3필드는 "판정과 주장은 화면 구획, 주소와 인용은 증거 구획"으로 다시 쓰고(필드 수 그대로), 미답변 조사 워커의 "확신도 | 근거: 경로" 형식은 "✔️(높음)나 ⚠️(중간과 낮음) 답 + 증거 구획"으로 바꾸며, plan-stage Researcher 프롬프트에는 증거 구획 지시와 화면 필드 경로 금지 각 한 줄을 둔다. 본체가 직접 쓰는 조사 답변도 화면 층 규격으로 쓰고 증거는 도구 결과(Read, WebFetch, 워커 보고)가 대신한다. plan-stage 로컬 정형(불릿 없음)은 짝 셈 면제 — 우선순위: HIGH
- REQ-005: 본체는 화면 층만 원문 그대로 옮긴다. 원문 전달 원칙의 적용 범위를 "화면 층의 원문"으로 적고, 증거 층도 본체가 고쳐 쓰지 않고 대조와 복사만 한다는 한 줄을 둔다. 규격 위반 판정에 셀 수 있는 조건 셋을 더한다 — 화면 층 ✔️ 줄 수와 증거 층 항목 수 불일치(⚠️ 줄은 세지 않음), 화면 층에 경로:행 패턴(REQ-012와 같은 정규식을 규범에 적음), 구분선 부재 → 재실행 1회 — 우선순위: HIGH
- REQ-006: 두 층 분리는 생산 규격 펜스 본문에 들어간다(실행 시점 복제). templates.md의 펜스 자리 두 곳과 257행 Contrarian 지시문 사본, plan-stage 96행의 로컬 정형 우선순위 문장, 그리고 펜스 밖 화면 생산 자리(templates.md 미답변 조사 프롬프트 136행과 조사 결과 제시 154행과 158행, brainstorming/SKILL.md 255행, plan-stage/SKILL.md Researcher 프롬프트 180~204행과 화면 210행, grounding.md 조사 워커 반환 규격 12~14행)를 함께 고친다. 구현 중 이 목록 밖으로 번지면 멈추고 초과분만 lessons.md에 적어 후속으로 넘긴다 — 우선순위: HIGH
- REQ-007: 출처 요청은 되물음이 아니다. decision-flow 「검증 규범」 아래 「근거 펼치기」 문단을 두고(신호 낱말 "출처", "근거 보여줘", "어디서" — 박스를 다시 내지 않고 📎 근거 메시지로 증거 층을 그대로 복사, 되물음 횟수와 밟은 갈래에 세지 않음, 여러 줄에 걸리면 전부 펼치고 한 줄도 안 걸릴 때만 자유 응답 한 줄), 되물음 갈래 표 바로 앞에 "출처 신호가 있으면 되물음이 아니다 — 갈래 판정 전에 「근거 펼치기」로 간다" 한 줄, 상시 주입본에 "출처 요청은 되물음이 아니다 — 박스 없이 📎 근거 메시지로 편다" 한 줄(약 60바이트 — 주입본 크기 유지 제약의 유일한 예외)을 둔다. 갈래 표와 사본 나열 셋(bootstrap, context-handling, workflow-orchestrator SKILL)은 그대로 — 우선순위: HIGH
- REQ-008: 펼치기 트리거는 자연어다. 조사 답변은 사용자 질문 번호("1번 출처")로, 결정 박스와 페르소나 발언은 줄 요지("아웃바운드 줄 출처")로 가리킨다. 페르소나 발언 화면에서 "출처 보여줘"만 오면 마지막 발언 한 명분을 펼치고 이름을 대면 그 사람 것을 펼친다. 가리키는 말이 여러 줄에 걸리면 전부 펼치고, 한 줄도 안 걸릴 때만 박스 없이 자유 응답 한 줄로 되묻는다 — 우선순위: HIGH
- REQ-009: 펼친 화면은 메시지 전체이고 고정 머리줄 `📎 근거 — [가리킨 것]` 앞에 문장을 두지 않는다. 아래에 "화면 줄 그대로 + 들여쓴 ↳ 증거 한 줄" 짝을 증거 층에서 그대로 복사한다. 결정 박스가 위로 밀리므로 메시지 끝에 "위 박스에 번호로 답해 주세요" 한 줄을 둔다. 머리줄 실물은 grounding.md 「고지 문구 실물」에 고정 문자열로 둔다 — 우선순위: HIGH
- REQ-010: 증거가 컨텍스트에 없으면(판정 조건: 그 발언의 `--- 증거 ---` 구획이나 증거로 쓴 도구 결과가 지금 컨텍스트에 없음 — 긴 세션에서는 압축 뒤 기본 경로) 재확인한다. 재확인은 본체 관문의 3출처 직접 확인 경로(501행)에 둘째 대상으로 잇고, `↳ 다시 확인 —`은 506행 갱신(REQ-011)과 한 차례에 묶는다 — 프로젝트 내 출처는 화면 문장으로 파일을 찾아 다시 읽고, 외부 출처는 조사 워커를 다시 돌린다(기존 진행 표시 문구 재사용). 다시 확인한 줄은 `↳ 다시 확인 — …`로 새 근거임을 밝힌다. 재확인 실패는 그 줄을 ⚠️로 강등하고 기존 강등 고지를 쓴다. 재확인 결과가 옛 줄과 다르면 기존 소급 반증 형식을 쓴다 — 우선순위: HIGH

- REQ-012: 사후 검사 `scripts/transcript-sources.mjs` — `transcript-dots.mjs`와 같은 구조(세션 jsonl과 subagents/agent-*.jsonl, assistant text 블록, main/worker 출처 열). main 출처 위반 수로 종료 코드, worker는 보고만. 위반 패턴: 옛 태그(확인 기호 뒤에 출처 낱말이 붙은 대괄호), 경로:행과 "N행"과 "N번째 줄", 따옴표 인용은 같은 줄에 경로나 주소나 ↳가 있을 때만. 코드 펜스 안과 `>` 인용 줄은 제외. 메시지 안 `📎 근거 — ` 이후 줄은 전부 제외. 파일 이름 단독은 세지 않는다. 머리 주석에 "모양만 센다, 사실 여부는 검사하지 않는다. 개발 세션은 실패가 정상, 통과 기준은 소비 세션 한 바퀴"를 적는다. 표본 같은 답변은 걸리고 출처를 뺀 판은 통과해야 한다 — 우선순위: HIGH

## 4. 설계 개요

지금 규범은 워커가 근거마다 `[✔ 출처]`와 증거를 한 줄에 붙여 돌려주고, 본체가 그 원문을 고치지 않고 화면에 올린다. 그래서 증거를 화면에서 빼려면 본체가 다시 써야 했고, 그것은 원문 전달 원칙과 비용 둘 다에 걸렸다.

바뀐 구조에서는 워커가 처음부터 두 층으로 돌려준다. 화면 층은 `- ✔️ 주장 1줄` 불릿(대상 이름을 문장 안에)이고, 증거 층은 항목마다 화면 줄을 반복한 뒤 `↳ 경로:행 — "인용"`을 잇는 번호 목록이다. 본체는 증거 층으로 관문 대조를 하고 화면 층만 그대로 옮긴다. 원문 전달 원칙은 화면 층에 적용되고, 증거 층은 대조와 복사만 한다.

사용자가 "출처 보여줘"나 "아웃바운드 줄 출처"라고 하면 본체는 박스를 다시 내지 않고 `📎 근거 — [가리킨 것]` 메시지에 증거 층을 그대로 복사해 편다. 증거 층이 컨텍스트에 없으면(압축, 세션 전환) 재확인해 `↳ 다시 확인 —`으로 새 근거임을 밝히고, 못 찾으면 ⚠️로 강등한다.

확인 여부는 아이콘 둘로 남는다. 이름표가 없는 자리는 줄마다 ✔️나 ⚠️, 이름표가 있는 자리는 이름표에 한 번. 세션 첫 고지가 두 아이콘의 뜻과 펼치기 부르는 법을 알린다.

재발은 규범 문구와 사후 검사가 잡는다. `scripts/transcript-sources.mjs`가 세션 기록의 본체 텍스트 줄에서 출처 표기 모양을 세고, `📎 근거 —` 이후 줄은 뺀다.

## 7. 제약조건과 가정

검증 장치는 약화하지 않는다. 태그 강등, 본체 관문, 워커의 근거 첨부 의무는 유지하고 화면 표시만 바꾼다. 본체가 매번 다시 쓰는 방식은 채택하지 않는다. 새 검사는 세션 기록을 사후에 세는 판정 도구로 한정하고 실행 시점 자동 검사기는 두지 않는다. 상시 주입본 크기는 늘리지 않고 실물 문구는 grounding.md에 둔다. 도메인 문서와 feature 문서의 평문은 불릿으로 내리지 않는다. 버전은 scripts/bump-version으로 두 파일을 함께 올린다. 커밋과 푸시는 마무리 절차에서만 한다.

가정은 넷이다. 증거는 워커가 여전히 생산해 본체가 대조한다 — 사라지는 것은 화면 노출이지 생산이 아니다. 걷어낸 증거는 압축 전까지 워커 반환물(도구 결과) 안에 남아 있고, 그 뒤는 재확인 경로다(압축이 서브에이전트 반환물을 지우는 것은 Claude Code의 보고된 동작이라 긴 세션에서는 재확인이 기본 경로가 된다). 출처 문자열 제거만으로 읽기 문제가 대부분 해소된다 — 표본의 두 번째 판이 근거다. 본체가 두 구획을 자르는 일은 모델이 하므로 확률적이고, 안전망은 규격 위반 재실행 1회다.

근거는 세션 안에서만 펼쳐진다. 설계 문서의 확인된 사실에는 근거가 남지 않으므로, 나중에 되짚으려면 저장소를 다시 확인해야 한다.

## 8. 기술 가이드라인

- 생산 규격 펜스에 두 층 구획 이름, 화면 층 불릿 모양, 증거 층 항목 모양, 셈 대상(근거 불릿만), 구분선 부재가 규격 위반이라는 것을 모두 적는다 — 펜스 밖 보조 문서에 두면 워커 프롬프트에 안 실린다
- 규격 위반 판정은 셀 수 있는 조건만 — 아이콘 수와 항목 수 불일치, 화면 층 경로:행 패턴, 구분선 부재. 결론 줄과 전제 반박 줄은 세지 않는다
- 펼친 메시지는 `📎 근거 — ` 머리줄로 시작하고 앞에 아무 문장도 두지 않는다. 「내보내기 전 검사」 곁가지 항목과 같은 결로 적는다
- "N번"은 조사 답변의 사용자 질문 번호에만 쓴다. 고지 문구의 예시도 "출처 보여줘"만 둔다
- 재확인은 프로젝트 내 출처부터 — 화면 문장으로 파일을 찾아 읽고, 못 찾으면 강등한다. 기억으로 경로와 행 번호를 지어내지 않는다
- 사후 검사의 따옴표 패턴은 단독으로 세지 않는다 — 되물음 원문 인용과 보통 문장이 걸린다(이 세션 실측 674줄)
- 스윕은 residue 헬퍼에 대상 파일을 직접 지정한다. `scripts/sweep`의 docs 범위는 evidence 67건 때문에 0건이 안 나온다
- 잔존 스윕 범위는 skills 밖(README, commands, CLAUDE.md, 도메인 문서 본문)까지 — 도메인 문서 변경 이력의 옛 모양 인용은 제외 목록에
- 이 환경의 grep은 이모지를 못 잡는다 — 아이콘 검사는 바이트 패턴이나 `LC_ALL=C`로 한다 (middle-dot-removal 선례)
- 관측 항목: 출처가 사라진 뒤 사용자의 근거 확인 요청 빈도, 펼친 화면에 출처 종류 한 낱말 두기, 페르소나 발언 전부 펼치기의 길이 — 실사용 뒤 판단
