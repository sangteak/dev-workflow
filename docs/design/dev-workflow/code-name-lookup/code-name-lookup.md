# code-name-lookup 설계 문서

> 한 줄 요약: 화면과 설계 문서에서 코드 이름이 한국어 번역어("배정"·"충원")나 지어낸 개념어("배선")로 바뀌어 나가는 것을 막는다 — 번역 금지·지어낸 이름 금지 조항에 실행 시점(코드 자리 대조)을 주고, 세션 동안만 사는 코드 이름 목록으로 읽는 순간의 번역을 막는다.

## 1. 배경과 동기

- 사용자 요청 원문: "아직 어색한 번역들이 좀 있어. 예를 들어 배선, 배정과 같이 어색한 부분들이 있고, 실제로 OpenMatch를 사용하기 때문에 Assignment, Backfill 등 코드를 사용 중임에도 불구하고 이걸 그대로 사용하지 않고 번역되어 사용하고 있어. … 실제로 이런 부분들로 인해 글이 잘 읽히지 않는 상황이 존재한다는 팀원들의 의견도 있었어."
- 되물음 사례 114건(`../reask-reassembly/evidence/reask-cases-all.md`)에서 `충원` 21회 · `배정` 7회 · `배선` 2회. 사례 152행에서 사용자가 이미 "번역하지 말고 그대로"라고 정정했고, 그 뒤 세션에서도 박스 제목에 "배정 요청"이 쓰였다. 규범 269행은 `Assignment`→"배정"을 금지 예시로 들고 있다 — **문장이 있어도 세지 않으면 안 지켜진다**(되물음 원인 1과 같은 구조).
- 원인 셋: ① 규범에 세는 단계가 없다(검사 1번은 풀이 유무만 센다, 번역어는 평범한 한국어라 후보에 안 든다) ② 번역이 쓰는 순간이 아니라 읽는 순간에 일어난다(코드를 읽으며 머릿속 요약을 한국어로 만든다) ③ 프로젝트에 코드 이름 목록이 없다(`01_GW-Server`에 `.claude/rules/` 없음, 코드에는 `Backfill` 322회·`Assignment` 147회).

## 2. 목표와 비목표

### 목표
- GOAL-001: 화면을 내보내기 전에 도메인 명사가 코드 이름의 번역어인지 세는 실행 시점을 규범에 준다
- GOAL-002: 세션 동안만 사는 코드 이름 목록으로 읽는 순간의 번역을 막고 풀이를 재사용한다 — 파일·메모리를 세션 밖에 남기지 않는다
- GOAL-003: 팀원이 읽는 설계 문서에도 같은 대조가 닿게 한다

### 비목표
- 저장소에 남는 사전 파일(`.claude/rules/terms.md`)과 그 유지·공유 — "작업하지 않는 부분을 기록하고 메모리에 올릴 필요가 없다"
- 세션 시작 상시 주입에 목록을 싣는 것 — CLAUDE.md를 작게 두고 참조를 거는 원칙과 어긋남
- phase 파일에 목록을 넣는 것 — 국면 0에는 자리가 없고 불변 규칙과 부딪힘
- `.superpowers/terms/` 별도 파일 — HANDOFF 절과 겹치는 두 번째 세션 파일
- 후보를 여럿 검색하거나 0건일 때 사용자에게 묻기 — 검색·되물음 증가
- 소비 프로젝트 기존 설계 문서의 일괄 정리 — 다른 저장소의 일
- 훅으로 강제하는 자동 검사 — 본체 판단으로 둔다
- 표준 개발 용어(리팩터링·의존성…)를 대조 대상에 넣는 것 — 265행이 그대로 쓰라고 정한다

## 3. 확정된 요구사항

- REQ-001: **언어 규범에 대조 항목.** `decision-flow.md` 언어 규범 펜스(268행 "내보내기 전에 풀이 없는 것을 센다" 옆)에 한 줄: "화면에 쓴 도메인 명사(표준 개발 용어 제외)는 세션 코드 이름 목록에 있거나 지금 다루는 코드 자리에서 **1건 이상** 나와야 한다. 없으면 영문 후보 하나를 코드 자리에서 검색해 1건 이상이면 그 이름으로 되돌리고 처음 자리에 풀이, 0건이면 설명 문장으로 편다(「저장소에 없는 낱말로 개념에 이름을 붙이지 않는다」 조항의 출구). 목록이 없으면 검색만 한다." 후보 검색 0건이면 목록을 갱신하지 않는다. 고정 문구 `코드 자리에서 1건 이상` — 우선순위: HIGH
- REQ-002: **검사 1번이 부른다.** 429행 "세는 것은 풀이 유무 하나다"를 "풀이 유무와 코드 자리 대조 둘"로 고치고, 432행의 판정형·개방형 예외를 대조 항목도 그대로 물려받는다. 검색은 git grep 또는 gitignore를 존중하는 검색으로 워크트리 안에서만 — 우선순위: HIGH
- REQ-003: **세션 코드 이름 목록 — 국면 0.** brainstorming 국면 0에서 카테고리 확정 응답을 받은 **같은 차례**에: 사용자 발화의 코드 이름(백틱·대문자 식별자)·경로 조각을 검색해 걸린 파일 경로들의 **가장 긴 공통 접두 디렉토리**를 자리로 잡고(절반 문턱 없음), 그 자리의 외부로 드러난 타입 선언 이름을 뽑아 **어간 단위**로 묶어 컨텍스트에 둔다(어간 · 어간의 뜻 · 코드 자리 · 구체 타입 몇 개, 스무 줄 안팎). 자리의 타입 선언이 60개를 넘으면 걸린 파일이 가장 많은 하위 디렉토리 둘로 내린다. 발화에 단서가 없으면 자리를 잡지 않고 첫 검색 때로 미룬다. 시드·작업 방향으로 자리 문자열이 달라지면 다시 훑는다. 국면 0 본문은 네 단계 산문("같은 차례" 규정 포함)으로 적고 bash 실물은 표 파일의 펜스 스니펫에 둔다(`scripts/`는 배포 밖). 계획 순서: REQ-004 → REQ-003 — 우선순위: HIGH
- REQ-004: **이름 추출 표.** `skills/workflow-orchestrator/references/code-name-patterns.md` 신설 — 언어 · 선언 패턴 · 어간 자르기 규칙 표(Go `^type [A-Z]`, TypeScript `export (class|interface|type|enum)`, C# `public (class|interface|record|struct|enum)`, Python `^class`, Rust `pub (struct|enum|trait)`, proto `^message [A-Z]`; 어간은 카멜 대문자 경계 첫 조각·스네이크 `_` 앞 조각; `Mock`·`Noop`·`Fake` 접두는 버림; 첫 조각이 두 글자 이하이거나 다음 조각이 대문자로 이어지면 둘째 조각까지 — `PreDigest`는 `PreDigest`). 규범 본문(brainstorming 국면 0)은 "외부로 드러난 타입 선언"이라고만 적고 표를 Read해 순회한다. 표에 없는 언어는 목록 없이 검색만. 표에 도착 문면 `^message`를 검사에 건다 — 우선순위: HIGH
- REQ-005: **고지 한 줄.** 국면 0 확정 박스 다음 차례, 첫 브레인스토밍 화면 앞에 단독 통보문: `📇 코드 이름 목록 N개를 이 세션에 두었습니다 — [자리]. 화면에서 이 이름들은 원문 그대로 씁니다.` 비었을 때도 이유 한 줄(자리 못 잡음 / 표에 없는 언어). 목록은 펼치지 않는다. 결정 박스와 같은 메시지에 두지 않는다. 국면 0 본문에 "고지는 통보문이라 「내보내기 전 검사」 ⑤의 대상이 아니다" 한 줄 — 우선순위: HIGH (REQ-013 통과 기준 첫 항목)
- REQ-006: **목록의 자리 — HANDOFF 절.** 국면 0~B-1은 컨텍스트, B-1 "같은 차례" 목록에 「코드 이름 목록」 절 옮기기를 한 항목으로 더한다. 절은 「결정 흐름 상태」 밖 별도 절, 머리 한 줄(자리 · 개수 · 뽑은 시점) + 어간 불릿. 국면마다 갱신, 마무리 Step 7에서 HANDOFF와 함께 사라진다. `decision-flow.md` 169행 `/compact` 직전 보존 목록에 추가. 목록이 없으면 절을 두지 않는다(생략 조건 한 줄) — 우선순위: HIGH
- REQ-007: **복구.** `context-handling/SKILL.md` 복구 절차에 항목 하나: 절의 자리 문자열이 현재 대상(시드·작업 방향, 그 전이면 발화 단서)과 같으면 그대로, 다르면 다시 훑고, 절이 없으면 첫 검색 때 — 우선순위: MEDIUM

## 4. 설계 개요

- 정본은 `decision-flow.md` 하나다. 대조 항목은 언어 규범 펜스에 살고(모든 사용자 대면 문면·워커 프롬프트 복제), 검사 1번이 박스 자리에서 부른다. 문맥 판정은 목록이 아니라 **지금 다루는 코드 자리의 검색**이 한다 — OpenMatch와 무관한 자리에서는 `Assignment`가 검색에 안 걸리므로 그 낱말이 화면에 올 이유가 없다.
- 세션 코드 이름 목록의 한살이: 국면 0(카테고리 확정 같은 차례) 추출 → 컨텍스트 → B-1에서 HANDOFF 「코드 이름 목록」 절 → 국면마다 갱신·복구가 읽음 → 워커 프롬프트 `--- 코드 이름 목록 ---` 구획으로 복제 → 마무리 Step 7에서 HANDOFF와 함께 삭제. 커밋·공유 목적의 파일은 없다.
- 세 단계(REQ-001): ① 목록 ② 영문 후보 하나 검색(코드 자리) ③ 설명 문장. 명사당 검색 최대 1회. 검색은 git grep·gitignore 존중.
- 자리 추정(REQ-003): 발화 단서 검색 → 가장 긴 공통 접두 → 타입 선언 60개 초과면 하위 둘 → 어간 묶기(표의 예외 규칙).
- 확인 절차는 별도 재생성 단계가 아니다 — 조립 중 점검, 비용은 검색 호출 몇 번(명사 수 이하)과 국면 0의 한두 번.

## 8. 기술 가이드라인
