## 확정 결정 (7)

1. **다시 실행 때 미리 체크 기준**: 지난 system 목록만. 첫 빌드 뒤 새로 생긴 산출물 폴더는 체크 안 된 채 보인다. 이유: 화면에 보이기만 하면 사용자가 체크하면 된다.
2. **user 부분 `exclude` 줄 모양**: 이름 줄(`Temp`)과 경로 줄(가운데 `/`가 든 줄) 둘 다 받는다. 경로 줄은 어느 깊이에서도 맞는 폴더가 디스크에 없으면 알린다. (결정 5로 경로 줄의 뜻이 "어느 깊이든"으로 바뀜)
3. **Grep 확인 시작 폴더**: 세션 폴더. (처음에는 세션 폴더와 루트 두 곳이었으나 결정 4로 두 폴더가 늘 같아져 한 곳으로 줄었다)
4. **`.ignore`를 둘 자리** (사용자 0번 응답): 세션을 연 폴더에서만 적용한다. 위로 올라가며 찾지 않는다. 세션 폴더에 `.p4ignore`(없으면 `p4ignore.txt`)가 없으면 "루트에서 세션을 여세요"로 멈춘다. `.ignore`와 `.claude/ignore.yaml`도 세션 폴더에 둔다.
   - 사용자 원칙: `.p4ignore`는 프로젝트 담당자가 쓰고, `.ignore`는 그 작성자 의도대로 동작하면 된다. 너무 깊은 하위에서 연 세션은 무의미하고, `.p4ignore`는 대개 루트나 작업 폴더 기준으로 쓰인다. 단순하게.
5. **`.ignore` 줄 모양**: 폴더 줄 `X/`를 `**/X/`로 옮긴다. system 줄과 user 줄 모두 같다. Perforce가 줄을 읽는 방식과 같다.
6. **`.ignore` 머리 둘째 줄**: 팀원용 "yaml이 없으면 명령만 실행"은 넣지 않는다. 문구: "직접 고치면 다음 실행 때 사라집니다. `.claude/ignore.yaml`의 user 부분을 고친 뒤 `/dev-workflow:search-ignore`를 다시 실행하세요". 팀원이 yaml 없이 `.ignore`만 받는 상황은 README 제출 안내로.
7. **Node.js가 없을 때** (합의, 결정 박스 없음): 아래 합의 항목 참조.

## 합의로 정한 것 (결정 박스 없음)

- 화면에서 폴더를 더하는 입력은 만들지 않는다. `.p4ignore`에 없는 폴더는 user 부분 `exclude`에 적고 다시 실행한다. 후보 화면 아래 한 줄로 알린다.
- Grep 확인이 실패해도 만든 파일은 그대로 두고 원인 후보(`.rgignore` 존재, 하위 폴더 무시 파일)를 알린다. 되돌리지 않는다.
- 확인 대상은 모양별 대표 하나씩(system 이름 줄, user 이름 줄, user 경로 줄). 텍스트 파일만 고르고 그 파일에만 있는 문자열로 찾는다(바이너리는 ripgrep이 원래 건너뛰어 거짓 통과). 확인할 파일이 없는 모양은 "확인 못 함"으로 따로 알린다. 확인은 `path`로 제외 폴더를 직접 주지 않고 세션 폴더에서 검색한다.
- 머리 주석: `.ignore`의 모든 줄은 `#`로 시작한다. 첫 줄 앞부분 고정 문자열이 소유 표지이고 판별 전에 BOM과 CR을 떼어 낸다. 버전 번호는 표지에 넣지 않는다. 둘째 줄은 경고와 고치는 길, 셋째 줄은 `# source: .p4ignore`(실제 원본 이름). 생성 시각과 해시는 넣지 않는다(같은 입력이면 같은 출력). yaml system 구획은 시작 표지와 끝 표지로 감싼다. user 부분 주석은 처음 만들 때 한 번만 쓰고 버전을 타지 않는 내용만 넣으며, 예시는 `Temp`처럼 실재할 이름을 쓴다.
- Node.js: 따로 `node --version` 단계를 두지 않는다. 첫 스크립트 호출(후보 목록 계산, 사용자와 주고받기 전)이 실패하면 멈추고 "Node.js 18+가 필요합니다. 파일은 바꾸지 않았습니다. `/dev-workflow:setup`으로 진단하세요"를 보인다. 찾을 수 없음(종료 코드 127) 말고 다른 실패면 원래 오류도 함께 보인다(오래된 Node 대비). 스크립트는 머지 도구와 같이 `--target=node18`로 묶는다. 모델이 대신 `.ignore`를 써 주는 대체 경로는 두지 않는다(결정성, 그리고 머리 주석을 흉내 내면 다음 실행이 명령 소유로 오인). 기존 "Node가 없으면 머지 기능만 비활성" 문구 세 곳(`commands/setup.md`, `README.md`, `CLAUDE.md`)을 이 명령까지 포함하게 고친다.

## 측정 사실 (2026-09-30, 고정 폴더와 GW)

- `p4 ignores`(GW): Perforce는 모든 줄을 `ROOT/X/...`와 `ROOT/.../X/...` 둘로 푼다. 가운데 `/`가 있어도 어느 깊이든 적용된다. 예: `Docs/.local/` → `GW/Docs/.local/...`, `GW/.../Docs/.local/...`.
- GW에서 `p4 info`는 설정된 작업공간(루트가 다른 폴더)을 답하고 `p4 where ...`는 "not under client's root". p4 조회로 Perforce 여부를 판정하면 GW에서 멈춘다 → 판정은 파일 존재로.
- Claude Grep은 상위 폴더 `.ignore`를 읽는다. 루트 `.ignore`의 줄이 `path`로 하위 폴더를 준 검색에서 먹는지는 모양에 따라 갈린다.
  - 먹음: `Temp/`, `**/Temp/`, `GW/Docs/`, `GW/Source/Temp/`
  - 안 먹음: `**/Temp/*`, `GW/Temp/*`, `GW/Source/Temp/*`, 그리고 `**/Saved/Autosaves/`, `**/Plugins/*/Binaries/`(`**/` 뒤 여러 단어)
  - 터미널 rg 15.2.0은 위 줄을 모두 제대로 뺀다(Claude Grep 쪽 차이)
- 세션 폴더(루트)에서 검색하면 `**/Saved/Autosaves/`, `**/Plugins/*/Binaries/`는 두 깊이 모두에서 빠지고 `Saved/Config`, `Plugins/A/Source`는 남는다.
- 폴더째 모양이어도 `path`로 그 폴더를 직접 주면 파일이 보인다(잠깐 보기 유지). `**/X/*`가 바로 위 폴더 `.ignore`에 있으면 직접 줘도 안 보인다.
- `/Temp/`는 `.ignore`가 있는 폴더 바로 아래 `Temp`만 뺀다(정상).

## README로 갈 것 (추가분)

- 하위 폴더를 `path`로 지정한 검색에서는 `**/` 뒤 여러 단어 줄(`Saved/Autosaves/`)이 먹지 않는다. GW는 `Saved/`, `Binaries/`, `Intermediate/`가 한 단어 줄로 따로 있어 영향이 없다.
- 세션은 `.p4ignore`가 있는 폴더에서 연다.
- 팀원이 yaml 없이 `.ignore`만 받고 명령을 다시 실행하면 작성자의 user 줄이 빠진다(제출 안내).
- `P4IGNORE`로 다른 파일 이름을 쓰는 저장소, 하위 폴더에 `.p4ignore`가 따로 있는 저장소는 이번 버전 범위 밖.
