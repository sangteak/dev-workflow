# perforce-search-ignore 설계 문서

> 한 줄 요약: Perforce 저장소에서 사용자가 부르는 명령 하나로 `.p4ignore`의 폴더 줄을 확인받아 `.ignore`를 만들고, Claude Code Grep 검색에서 빌드 산출물을 뺀다.

## 1. 배경과 동기

- Perforce 저장소에는 `.gitignore`가 없어서 Claude Code Grep 도구가 빌드 산출물까지 훑는다. GW(UE5 C++)는 C++ 파일 56,745개 중 86%가 `Intermediate/` 생성 코드다.
- 이전 세션에서 제외 없는 루트 검색은 Grep 도구의 20초 제한에 걸리거나 결과가 흔들렸다(같은 검색이 6파일과 8파일).
- Grep 도구는 git 밖에서도 `.ignore`를 지킨다(실측). 그런데 Perforce 저장소에는 산출물 목록이 이미 `.p4ignore`로 있다. 이를 옮겨 쓰면 된다.
- 기성 검색 도구를 들이는 길은 실측 끝에 기각했다(코드 검색 도구 조사, 2026-09-28). 이 기능은 도구를 추천하지 않는다.

## 2. 목표와 비목표

### 목표
- GOAL-001: `.p4ignore`가 있는 폴더에서 연 세션의 Claude Grep 검색이 `.p4ignore` 작성자가 뜻한 산출물 폴더를 빼고 검색한다. GW 실측 기준: `Intermediate` 안 161파일이 결과에서 빠지고, 터미널 rg 시간이 7초에서 3.3초로 준다.
- GOAL-002: 사람과 Claude는 `.claude/ignore.yaml`만 고치고, `.ignore`는 명령이 만든다. 같은 입력이면 같은 출력이 나온다.

### 비목표
- git 저장소 지원: ripgrep이 `.gitignore`를 이미 지킨다.
- 기본 설치, 자동 생성, 세션 시작 훅 알림: 사용자가 상황에 맞게 부르는 명령이다. 훅 알림은 다음 버전 후보.
- 제출: `.ignore`를 제출할지는 사용자 몫이다. 명령은 "`p4 reconcile`에 새 파일로 잡힘"만 알린다.
- 위로 올라가며 루트 찾기: 세션 폴더에서만 동작한다. 너무 깊은 하위에서 연 세션은 의미가 없고, `.p4ignore`는 대개 루트나 작업 폴더에 있다.
- `keep`(안쪽 되살리기), 본문 해시 비교, "이 저장소에서는 쓰지 않음" 선택지, `!` 줄 알림: 다음 버전.
- Glob 도구 설정 자동 변경: 명령은 설정 파일을 고치지 않고 방법만 안내한다.
- `P4IGNORE`로 다른 이름을 쓰는 저장소, 하위 폴더에 따로 있는 `.p4ignore`: 범위 밖(README에 적음).

## 3. 확정된 요구사항

- REQ-001: 명령 `/dev-workflow:search-ignore`를 `commands/`에 둔다. 사용자가 명시적으로 부를 때만 동작하고, Perforce 저장소 전용이다. — 우선순위: HIGH
- REQ-002: 세션 폴더에 `.p4ignore`, 없으면 `p4ignore.txt`가 있을 때만 동작한다. 둘 다 없으면 "`.p4ignore`가 있는 폴더에서 세션을 여세요"라고 알리고 멈춘다. 위로 올라가며 찾지 않고, git 검사와 `p4` 조회도 하지 않는다. — 우선순위: HIGH
- REQ-003: 후보 화면 — 우선순위: HIGH
  - `.p4ignore`에서 BOM, 줄 끝 CR과 앞뒤 공백을 걷고 `#` 줄, 빈 줄, `!` 줄, 파일 줄을 뺀다. `/`나 `/**`로 끝나는 줄이 폴더 줄이다.
  - 폴더 줄 가운데 디스크에서 맞는 폴더가 있는 것만 번호 붙은 행으로 보인다. 존재 확인은 깊이와 상관없이 한다.
  - 좁은 산출물 이름 9개(`Intermediate`, `DerivedDataCache`, `Saved`, `Binaries`, `node_modules`, `__pycache__`, `.gradle`, `.venv`, `venv`)에 맞는 행은 미리 체크한다. 맞춤은 경로 마지막 조각을 대소문자 무시로 한다. `Build`는 넣지 않고, 도구 폴더(`.claude/`, `.vs/`)는 미리 체크하지 않는다.
  - 체크된 한 단어 줄에 이미 포함되는 행(`Saved/`가 체크됐을 때의 `Saved/Autosaves/`)에는 "(체크된 `Saved/`에 포함)"을 붙이고 체크 칸은 비운다.
  - 기본 수락: 확인 한 번으로 통과하고, 바꿀 행은 번호로 켜고 끈다.
  - 화면 아래에 "`.p4ignore`에 없는 폴더는 `.claude/ignore.yaml`의 user 부분에 적고 다시 실행하세요"를 한 줄로 보인다.
  - `.p4ignore` 철자와 디스크 철자가 대소문자만 다른 폴더를 만나면 한 줄로 알린다(`.ignore`는 대소문자를 가린다). 디스크 존재 확인만으로는 못 잡으므로 폴더 목록의 이름을 직접 비교한다.
  - `*` 대조는 조각 단위(`*`를 `[^/]*`로, 조각 수 일치)로 직접 짠다. `path.matchesGlob`는 Node 18에 없어 쓰지 않는다. 가운데 `**`, `?`, `[]`가 든 줄은 후보에서 빼고 한 줄로 알린다.
  - 가운데 `/`가 든 줄(`Saved/Autosaves/`)은 세션 폴더 기준 상대 경로와 조각 수가 같을 때만 맞는다(`.ignore`의 앵커 규칙과 같음).
- REQ-004: 다시 실행하면 후보는 매번 새로 계산하고, 미리 체크는 지난 system 목록을 따른다. 새로 생긴 산출물 폴더는 체크 안 된 채 보인다. — 우선순위: MEDIUM
- REQ-005: 원본은 세션 폴더의 `.claude/ignore.yaml`이다. — 우선순위: HIGH
  - system 부분은 명령 소유이고, 시작 표지와 끝 표지로 감싼다.
  - user 부분은 사람 소유이고, 명령은 처음 만들 때 한 번 쓴 뒤로 손대지 않는다.
  - 키는 `exclude` 하나다.
  - user 부분 주석은 버전을 타지 않는 내용만 적고, 예시는 `Temp`처럼 실재할 이름을 쓴다. "`*`나 `!`로 시작하는 줄은 따옴표로 감싼다"를 싣는다(따옴표 없는 `*venv/`는 yaml 별칭 오류, `!foo/`는 빈 문자열이 됨).
  - system 구획은 항목마다 JSON 문자열 이스케이프로 따옴표를 쓴다.
  - user 부분 파싱이 실패하면(`errors` 배열과 `toJS()` 예외 둘 다 검사) 아무 파일도 쓰지 않고 실패 위치를 알린 뒤 멈춘다.
- REQ-006: 생성은 플러그인 안의 Node 스크립트가 한다. — 우선순위: HIGH
  - yaml 라이브러리를 개발 때 esbuild로 묶고(`--target=node18`), 머지 MCP 번들과 따로 둔다.
  - 명령은 Bash 도구로 `node "${CLAUDE_PLUGIN_ROOT}/mcp/dist/search-ignore.js"`를 부른다. 이 변수는 명령 본문이 로드될 때 절대 경로로 치환되고(공식 문서), Bash 환경 변수로는 들어오지 않는다.
  - `mcp/package.json`의 빌드 명령과 테스트 목록에 새 대상을 적는다. 스크립트 원본은 MCP 서버 모듈을 가져다 쓰지 않는다.
  - 두 번 부른다. 첫 호출은 후보 계산이고, 둘째 호출은 같은 입력으로 다시 계산한 뒤 체크된 행 번호만 받아 쓴다. 첫 호출이 낸 입력 요약값이 둘째 호출에서 다르면 멈춘다.
  - `.ignore` 줄은 `.p4ignore`에서 고른 줄과 user 부분 줄을 **그대로** 옮긴다. `**/`를 붙이거나 모양을 바꾸지 않는다.
- REQ-007: `.ignore` 머리 주석은 세 줄이고, 모든 줄이 `#`로 시작한다. — 우선순위: HIGH
  - 첫 줄 앞부분 고정 문자열이 소유 표지다. 판별 전에 BOM과 CR을 걷고, 버전 번호는 넣지 않는다.
  - 둘째 줄: "직접 고치면 다음 실행 때 사라집니다. `.claude/ignore.yaml`의 user 부분을 고친 뒤 `/dev-workflow:search-ignore`를 다시 실행하세요"
  - 셋째 줄: `# source: .p4ignore` (실제 원본 이름)
  - 생성 시각과 해시는 넣지 않는다.
  - 소유 표지가 없는 `.ignore`가 이미 있으면 건드리지 않고 멈춘다. 이때 "기존 `.ignore`를 지우거나 이름을 바꾼 뒤 다시 실행하세요. 남길 줄은 그 전에 적어 두었다가 `.claude/ignore.yaml`의 user 부분에 옮기세요"라고 알린다.
- REQ-008: 생성 뒤 Grep으로 확인한다. — 우선순위: HIGH
  - 스크립트가 모양별로 제외 폴더 안 대표 텍스트 파일 하나와, 그 파일의 정규식 특수문자 없는 긴 줄(24자 이상)을 고른다(system 줄 하나, user 줄이 있으면 하나).
  - 양성 대조: 먼저 `path`를 그 제외 폴더로 준 Grep으로 문자열이 실제로 찾아지는지 본다. 이 호출만 아래 "`path`를 비운다" 규칙의 예외다. 안 찾아지면 "확인 못 함".
  - 본 확인: 세션 폴더에서 `pattern`, `output_mode: files_with_matches`, `head_limit: 0`만 준 Grep을 부른다. `path`, `glob`, `type`은 비운다.
  - 판정은 결과 건수가 아니라 돌아온 경로로 한다. 제외 폴더 안 경로가 하나라도 있으면 실패다.
  - 결과는 셋이다. 통과, 실패(원인 후보를 붙임: `.rgignore` 존재, 하위 폴더 무시 파일), 그리고 확인할 파일이 없을 때의 "확인 못 함".
  - 시간 초과는 "제외 안 됨"과 구분해 알린다.
  - 실패해도 만든 파일은 그대로 둔다.
- REQ-009: Node.js가 없을 때 따로 확인하는 단계는 두지 않는다. — 우선순위: MEDIUM
  - 첫 스크립트 호출이 실패하면 "Node.js 18+가 필요합니다. 파일은 바꾸지 않았습니다. `/dev-workflow:setup`으로 진단하세요"를 보이고 멈춘다.
  - 종료 코드가 127(명령 없음)이 아니면 원래 오류를 덧붙인다.
  - 모델이 대신 `.ignore`를 써 주지 않는다.
- REQ-010: 명령 끝 안내 — 우선순위: MEDIUM
  - 되돌리기 방법: 잠깐 보려면 `path`로 폴더를 직접 지정, 영구히 바꾸려면 yaml을 고친 뒤 다시 실행, 그만 쓰려면 두 파일을 삭제.
  - "`.ignore`는 `p4 reconcile`에 새 파일로 잡힙니다".
  - Glob 도구에도 적용하는 방법: `.claude/settings.local.json`의 `env`에 `CLAUDE_CODE_GLOB_NO_IGNORE: "false"`를 넣고 세션을 다시 연다.
- REQ-011: README에 이 명령 절을 둔다. 다음 한계를 적는다. — 우선순위: MEDIUM
  - 가운데 `/`가 든 줄(`Saved/Autosaves/`)은 `.ignore`에서 세션 폴더 기준이다. 어느 깊이든 빼려면 user 부분에 `**/`를 붙여 적는다.
  - Glob 설정 방법(REQ-010).
  - macOS, Linux와 WSL에서는 Grep 도구가 없을 수 있다.
  - 팀원이 yaml 없이 `.ignore`만 받고 명령을 다시 실행하면 작성자의 user 줄이 빠진다.
  - `.ignore`는 터미널 rg에도 적용된다.
  - `P4IGNORE` 다른 이름과 하위 폴더 `.p4ignore`는 범위 밖이다.
  - 세션은 `.p4ignore`가 있는 폴더에서 연다.
- REQ-012: "Node가 없으면 머지 기능만 비활성" 뜻의 문구를 이 명령까지 포함하게 고친다. 범위는 파일 세 개, 줄 여덟 개 이상이다. `commands/setup.md` 다섯 줄(Step 2 제목 "MCP 실행 요건 진단" 포함), `README.md` 두 곳, `CLAUDE.md` 세 곳(Architecture 문단, `commands/` 목록 줄, `mcp/` 소개 줄)이고 `CLAUDE.md` 명령 표에 `search-ignore` 행을 더한다. 머지 스킬 자체의 도구 가용성 문구는 머지 전용이라 고치지 않는다. 고친 뒤 구 문구를 grep해 잔존을 확인한다. — 우선순위: MEDIUM

## 4. 설계 개요

```
사용자: /dev-workflow:search-ignore
  │
  ├─ 명령 문서(commands/search-ignore.md)가 흐름을 지시
  │
  ├─ ① Bash: node <번들> plan   ── 실패 → REQ-009 멈춤
  │     읽기: .p4ignore(또는 p4ignore.txt), .claude/ignore.yaml(있으면), 디스크 폴더
  │     검사: 원본 없음(REQ-002), 소유 표지 없는 .ignore(REQ-007) → 멈춤
  │     출력: 후보 행 목록, 미리 체크, 포함 표시, 입력 요약값
  │
  ├─ 모델이 후보 화면을 보이고 사용자 확인(행 번호 토글)
  │
  ├─ ② Bash: node <번들> apply --rows 1,3,5 --digest <요약값>
  │     다시 계산 → 요약값 비교 → yaml system 구획 교체(임시 파일, 이름 바꾸기)
  │     → .ignore 생성(머리 3줄 + system 줄 + user 줄, 그대로 옮김)
  │     출력: 확인용 대표 파일과 고유 문자열
  │
  ├─ ③ 모델이 Grep(pattern만) → 통과, 실패, 확인 못 함
  │
  └─ 끝 안내(REQ-010)
```

- 구현 모듈(`mcp/src/search-ignore/`, 의존은 한 방향): `p4ignore.ts`(폴더 줄 파싱) → `match.ts`(패턴 해석, 조각 단위 `*` 대조) → `scan.ts`(가지치기 순회) → `select.ts`(미리 체크, 포함 표시) → `yamlSource.ts`(yaml 읽기와 system 구획 교체, `StopError`), `ignoreFile.ts`(소유 표지, `.ignore` 조립), `probe.ts`(확인용 파일 고르기) → `cli.ts`(`plan`, `apply`, 요약값, 멈춤, 원자적 쓰기, JSON 출력). 진입점 `mcp/src/search-ignore.ts`, 번들 `mcp/dist/search-ignore.js`.
- 스크립트 출력 계약: stdout에 JSON 한 줄, 종료 코드 0 정상, 2 멈춤(`{status:"stop", reason, message}`), 1 내부 오류. 멈춤 reason은 `no-source`, `foreign-ignore`, `yaml-error`, `marker-error`, `digest-mismatch`, `bad-rows`, `read-only`.
- 세션 폴더에 생기는 파일은 둘이다. `.ignore`(검색 제외, 명령 소유)와 `.claude/ignore.yaml`(원본, system과 user).
- 판단이 필요한 계산(파싱, 디스크 대조, 미리 체크, 포함 판정, 파일 쓰기)은 모두 스크립트가 하고, 모델은 화면과 Grep 확인만 한다.

## 7. 제약조건과 가정

- 가정: Claude Code Grep 도구가 git 밖에서도 세션 폴더의 `.ignore`를 지킨다. 공식 문서는 `.gitignore`만 말하므로 업데이트로 바뀔 수 있다. 알아챌 장치는 REQ-008 확인뿐이다.
- 가정: 세션은 `.p4ignore`가 있는 폴더에서 연다.
- 제약: Claude Grep에 `path`로 하위 폴더를 주면, 세션 폴더 `.ignore`의 가운데 `/` 줄과 `/*` 끝 줄은 먹지 않는다. 한 단어 줄은 먹는다(실측).
- 제약: `.ignore` 줄은 대소문자를 가린다(Windows ripgrep 15.2.0 실측).
- 제약: Glob 도구는 설정 없이는 `.ignore`를 따르지 않는다(실측, 공식 문서).
- 제약: Node.js 18+가 필요하다. 네이티브 설치 Claude Code는 Node 없이 돌기도 한다.
- 제약: GW `.p4ignore`는 BOM과 CRLF를 쓴다.
- 제약: 읽기 전용 여부는 이미 있는 대상 파일만 미리 확인한다. 상위 폴더(`.claude/`)가 읽기 전용이면 임시 파일은 지워지지만 일반 오류(종료 코드 1)로 끝난다.
- 제약: 읽기 전용 확인은 `apply` 단계에서만 하므로, 사용자는 후보 화면에서 고른 뒤에 막힌다는 것을 안다.
- 확인 못 함: 파일 종류를 지정하지 않은 GW 루트 검색이 `.ignore`가 있어도 172파일과 174파일로 흔들린 원인.

## 8. 기술 가이드라인

- 순회는 한 번만 돌며 모든 폴더 줄을 동시에 대조하고, 맞은 폴더 안으로는 내려가지 않는다.
- `*`가 든 줄(`Plugins/*/Binaries/`)은 glob 대조로 존재를 가린다. `*venv/`처럼 이름 목록과 글자가 다른 줄은 디스크에서 맞은 폴더 이름으로 미리 체크를 판정한다.
- `/**`로 끝나는 줄(`Docs/.pending/**`)도 폴더 줄로 후보에 넣는다. `.ignore`에는 원문 그대로 옮긴다.
- yaml 구획 교체: 표지가 정확히 한 쌍이 아니면 멈춘다. 교체한 텍스트를 다시 파싱해 `exclude`가 목록인지 확인한다. 줄 끝 방식과 BOM을 지킨다. 임시 파일에 쓴 뒤 이름을 바꾸고, yaml을 먼저 쓰고 `.ignore`를 나중에 쓴다.
- 명령 문서에는 Grep 확인 호출 모양을 글자 그대로 적는다(`pattern`만). 고유 문자열은 정규식 특수문자가 없는 것으로 고른다.
- 스크립트 호출은 Bash 도구로 고정한다(PowerShell은 명령 없음 종료 코드가 다름).
- 번들은 머지 MCP와 따로 두고, 번들 커밋 방식이므로 src를 고치면 빌드를 같이 커밋한다.
- `mcp/package.json`의 `pretest`는 테스트 파일을 이름으로 나열하므로 새 테스트를 반드시 목록에 더한다.
- 소스에 BOM 같은 보이지 않는 문자를 날것으로 두지 않고 `﻿` 이스케이프로 쓴다. 지워지면 BOM 보존이 조용히 깨진다.
- 정렬은 로캘 무관한 코드 단위 비교로 한다(같은 입력 같은 출력).
- 파일 읽기는 `ENOENT`만 "없음"으로 보고 나머지 오류는 그대로 올린다(소유 표지 보호가 뚫리지 않게).

## 9. 구현 결과 및 일탈 사항

**구현 (2026-10-12, 브랜치 `feature/perforce-search-ignore`, 1.29.0)**
- `plan.md` 태스크 1~10을 Subagent-driven으로 구현했다. 태스크마다 리뷰를 거쳤고, 끝에 브랜치 전체 리뷰를 한 번 더 했다. 테스트는 기존 12개에 새 40개를 더해 52개가 모두 통과한다.
- 라이브 확인: `claude -p --plugin-dir`로 명령 본문의 `${CLAUDE_PLUGIN_ROOT}`가 워크트리 경로로 치환됨을 확인했다(Task 1). 작은 테스트 폴더에서 새 세션으로 후보 화면, 생성, 양성 대조 뒤 본 확인을 끝까지 돌렸다(Task 8).

**설계 대비 일탈 (구현 중 결정)**
- 한 조각 `X/**` 줄을 앵커로 다룬다. 계획 코드는 어느 깊이든으로 다뤘다(Task 2 리뷰).
- 처음 실행 미리 체크: 계획의 코드와 테스트가 서로 어긋나 있었다. 모든 줄을 판정한 뒤 덮이는 줄은 체크를 풀고 포함 표시를 붙이는 규칙으로 바꿨다(Task 4).
- 계획의 yaml 테스트 두 개가 user가 아니라 system 쪽을 시험하고 있어, user 쪽을 시험하도록 바꿨다(사전 점검).
- 브랜치 전체 리뷰에서 두 가지를 더했다. 읽기 전용 대상은 쓰기 전에 멈추고, `ENOENT`만 "없음"으로 본다. 또 BOM 이스케이프와 정렬 기준을 통일했다.
- 읽기 전용 멈춤 문구는 사용자 승인 문구로 정했다: 원인 줄, 빈 줄, "Perforce로 받은 파일이라면:" 아래 `p4 edit`과 `allwrite` 두 줄.

**남겨 둔 것 (다음 버전 후보)**
- `X/*`로 끝나는 줄이 알림 없이 빠진다.
- user 줄이 폴더 모양이 아닐 때 "확인 못 함" 사유가 "맞는 폴더가 디스크에 없음"으로 나온다.
- 명령 문서에 선택지 0 동작, 시간 초과 구분 문구가 없고, `allowed-tools`에 Grep이 없다.
- `select.ts` 두 분기에 같은 검사가 중복된다.
- 테스트 빈칸: 2000개 상한, 1MB, 200자 상한, 빈 `--rows`, `main` 종료 코드.
