BOM, CR, 앞뒤 공백 제거 후 `#`과 빈 줄 버림 |

전제 점검(🛠️): 설계는 "Grep 도구가 git 밖에서도 `.ignore`를 지킨다"는 실측에 기댄다. 업데이트로 사라지면 알아챌 장치는 생성 뒤 Grep 확인뿐이라 이 단계는 빼면 안 된다.

## 페르소나 검토 요지

- 🔍 Ecosystem Analyst: 공식 문서가 보장하는 것은 Grep의 `.gitignore` 존중뿐이고 `.ignore` 존중은 구현 세부(버전 변경 리스크). Glob 도구는 기본으로 무시 파일을 따르지 않음. `permissions.deny`의 Read 규칙은 공식 경로지만 최선 노력이고 Read까지 막아 대안이 되기 어려움. 전제 반박: macOS, Linux, WSL에서는 Grep과 Glob 도구가 기본 목록에서 빠지고 Bash 내장 grep이 대신함(`.ignore` 존중 미확인).
- 🎯 Workflow Designer: 머리 주석 없는 `.ignore` 멈춤 문구가 기존 파일을 치우라고 안 해서 같은 멈춤이 반복됨. "루트"라는 말이 GW에서 헷갈림(안쪽 `GW/`, p4 작업공간 루트). 후보 화면에서 체크된 줄에 포함되는 행이 "남는다"로 읽힘. 전제 반박: Grep 확인 통과가 곧 20초 제한 해소는 아님.

## 재협의와 최종 결정

1. **`.ignore` 줄 모양 (국면 2 결정 5 다시 봄, 사용자 2번)**: `.p4ignore` 줄을 그대로 옮긴다. `**/`를 붙이지 않는다. 더 필요한 줄은 사용자가 user 부분에 적는다. 따라온 변경: user 부분 줄도 변환 없이 그대로 옮김(국면 2 결정 2의 이름 줄과 경로 줄 변환 없어짐), 경로 줄 디스크 확인은 뺌(명령 끝 Grep 확인의 "확인 못 함"이 대신함).
2. **후보 화면의 포함된 행 (사용자 1번)**: 체크된 한 단어 줄에 포함되는 행 옆에 "(체크된 `Saved/`에 포함)"을 붙이고 체크 칸은 비운다. 묶거나 숨기지 않는다.
3. **Glob 한계 (사용자 2번)**: 명령은 설정 파일을 고치지 않는다. 명령 끝과 README에서 `.claude/settings.local.json`의 `env`에 `CLAUDE_CODE_GLOB_NO_IGNORE: "false"`를 넣고 세션을 다시 여는 방법을 안내한다.
