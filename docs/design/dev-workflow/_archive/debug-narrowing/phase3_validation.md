#### 1. 발동 규칙 한 줄이 더 강한 문장 두 개와 경쟁한다 (🛠️ Claude Code Expert)

⚖️ 판단: 한 줄 추가만으로는 모델이 안정적으로 움직이지 않을 가능성이 크다.

- [✔] `skills/workflow-orchestrator/SKILL.md:11, 193` 우리 문서 자신이 "Superpowers 스킬이 존재하면 FIRST 실행"이라 적어 새 구간을 앞에 두는 것과 정면으로 부딪힌다

#### 2. 판정선이 없는데 문서 자체가 "애매하면 켜라"로 기울어 있다 (🎯 Workflow Designer)

⚖️ 판단: 판정선 없이 어휘만 추가하면 멀쩡한 수정 요청까지 첫 화면에서 붙잡힌다.

- [✔] `bootstrap.md:13` "판단이 애매하면 invoke하는 쪽을 택한다" — 결함 신고는 대부분 애매한 중간대라 구조적으로 발동 쪽으로 기운다
- [✔] `skills/development-principles/SKILL.md:40~42` "버그 리포트 수신 시 사용자에게 하나하나 확인하지 않고 직접 해결한다" — 새 구간은 반대 행동을 하는데 어느 쪽이 이기는지 적힌 곳이 없다
- [추측] 완성 판정 1번의 두 예시는 양 끝점이고 실제 신고 대부분은 중간대다

#### 3. 잘못 열렸을 때 빠져나가는 길이 설계 어디에도 없다 (🎯 Workflow Designer)

⚖️ 판단: 발동이 첫 화면에서 일어나므로 탈출구가 없으면 사용자는 질문을 한 번 받은 뒤에야 벗어난다.

#### 4. 생태계는 전부 명시 명령으로 연다 (🔍 Ecosystem Analyst)

⚖️ 판단: 비교 대상 플러그인들은 디버깅 진입을 예외 없이 사용자가 직접 치는 명령으로 열고, 대화 어휘로 자동 감지하지 않는다.

- [✔] Compound Engineering 리드미 — 입력이 버그면 "브레인스토밍 → 계획 → 작업" 대신 재현·근본 원인 추적·수정으로 바로 간다
- [✔] feature-dev 명령 파일 12행 — 되묻기를 코드베이스 탐색 뒤로 일부러 밀어 놓았다
- [✔] superpowers 위반 신호표 40·43행 — "정보를 먼저 모으자"는 충동을 위반 신호로 못 박았다

## 반증 가능성에 대한 지적 (두 전문가 독립 일치)

> 완성 판정 5번은 "전달되는 것이 화면에서 확인된다"까지만 본다. 전달만 확인하고 그 덕분에 빨라졌는지는 보지 않으므로, **전제가 틀려도 아홉 기준이 모두 통과한다.** 관측으로 반증할 수 없는 설계이고, 그러면 "관측 후 확장"이라는 후속 계획도 판단 근거를 얻지 못한다. — 🛠️ Claude Code Expert

> 실패는 시끄럽게 오지 않고 이 구간이 조용히 안 쓰이는 모습으로 온다. 관측할 지표를 하나 잡는다면 발동 횟수가 아니라 **발동 후 끝까지 간 비율**이어야 한다. — 🔍 Ecosystem Analyst

> 나머지가 다 값을 못 해도 **증상 진술 자체를 되묻는 질문**은 빈칸으로 남는다. 사용자가 증상을 잘못 진술한 경우는 되묻기 말고 메울 수단이 없고, superpowers 1단계에는 사용자에게 묻는 절차가 아예 없기 때문이다. — 🔍 Ecosystem Analyst

## 🧭 기술 가이드라인 (셋을 합쳐 중복 제거)

1. 발동 판정을 말투가 아니라 **셀 수 있는 사실의 유무**로 쓴다 — 에러 원문·재현 절차·바뀐 지점 중 몇 가지가 신고에 들어 있는지
2. 첫 질문 줄에 **구간을 접는 탈출 문구**를 함께 노출한다 (예: "그냥 고쳐"라고 답하면 좁히기를 끝내고 바로 수정으로 간다)
3. **조기 종료 조건**을 둔다 — 상한에 닿거나 "모름"이 두 번 이어지면 남은 질문을 조사 우선순위로 옮기고 즉시 넘어간다
4. 증상 명세가 **신고 문장의 재진술뿐이면 아무것도 넘기지 않고** 그대로 통과시킨다
5. "Superpowers 먼저" 원칙에 이번 구간만의 **예외를 한 문장으로 명시**한다
6. `development-principles`의 자율 수정 규범과 좁히기 중 **무엇이 먼저인지 순서를 적는다**
7. bootstrap 12행을 고칠 때 `SKILL.md:167`과 `README.md:132`를 **같은 변경 묶음에서 함께** 고친다
8. bootstrap에 발동 문장과 **무효화 문장을 한 쌍으로** 넣는다 (원인이 적혀 있거나 파일·함수가 지목된 요청이면 해당 없음)
9. 좁힌 결과의 항목 이름을 superpowers 1단계의 세 가지와 **같게 맞춘다**
10. 사용자 답변에서 온 것과 코드에서 확인한 것을 **태그로 갈라** 넘긴다
11. 개발 중 비발동은 계획 파일 존재가 아니라 **"열린 계획의 태스크 범위 안인가"**로 판정한다
12. "파일로 남기지 않는다"를 상태 보존 규범의 **예외로 한 줄 못 박고**, 압축 직전에는 증상 명세를 대화에 다시 출력한다
13. "실행 기록도 근거로 본다"에 **"이 스킬 안에서만"**이라는 한정을 같은 줄에 붙인다
14. 전문가 발언을 하위 에이전트로 돌리면 언어 규범과 발언 규격 펜스를 **프롬프트에 통째로 복제**한다
15. superpowers가 **좁힌 범위 밖에서 원인을 찾은 경우 그 사실을 대화에 한 줄 남긴다** — 파일을 만들지 않으므로 기록 금지와 부딪히지 않고, 이 설계를 반증할 유일한 관측 수단이 된다
16. bootstrap 자동 테스트가 없으므로 **사람이 직접 두 문장을 넣어 보는 확인**을 계획의 첫 항목으로 둔다
17. 진행 표시의 전체 수를 미리 확정할 수 없으므로 **"최대 몇 개" 형태**로 쓰고 도중에 끝날 수 있음을 첫 줄에 밝힌다
18. 조사 우선순위 항목은 **"무엇을 어디서 확인하라"는 관찰 지시문으로만** 쓰고 "무엇 때문이다"라는 단정을 금지한다
19. 완성 판정 7번의 문면을 **"안내 줄이 나오는가"로 낮춰** 확정 제약(자동 분기 없음)과 맞춘다
20. 전문가 세트 파일이 없으면 **비판 라운드를 통째로 생략**하고 완성 판정 8번은 해당 없음으로 처리한다고 미리 적는다
21. 비판을 병렬로 돌리면 **대기 고지 한 줄**을 반드시 붙이고 인원을 둘로 묶어 대기를 짧게 유지한다
22. 완성 판정 5번은 superpowers를 하위 에이전트로 부르는 경로와 본 세션에서 직접 부르는 경로 **양쪽에서 각각** 화면 확인한다

**등급이 갈린 두 지점 — 인용 진위가 아니라 포착 범위의 차이였다**

- 새 구간을 superpowers 1단계 앞에 두는 순서 설계: 두 전문가의 인용이 모두 정확했다. 등급 차이는 `using-superpowers:62`("사용자 지시가 스킬보다 우선")가 실제로 얼마나 완화력을 갖는지에 대한 판단 차이에서 왔다. 🛠️ Claude Code Expert의 답변에는 62행에 대한 언급이 없었다
- 자율적 버그 수정 규범과의 충돌: 인용은 양쪽 다 정확했다. 🎯 Workflow Designer가 `bootstrap.md:13`("애매하면 invoke")을 함께 엮어 구조적 편향으로 확장하며 위험을 한 단계 올렸고, 🛠️ Claude Code Expert의 답변에는 13행에 대한 언급이 없었다

**본체 판정:** 두 조항 모두 실재한다. 62행은 완화 쪽으로, 13행은 악화 쪽으로 작동한다.

## 재협의가 발생한 항목과 최종 결정

### 재협의 — 발동 방식 (국면 2 결정 2의 재검토)

**국면 2 확정:** 발동 규칙 문서에 한 줄 추가. 관측 후 안 되면 슬래시 명령 병행으로 확장.

**국면 3 검증:** 높은 위험 네 건 중 세 건이 "자동 판정이 경쟁에서 진다" 또는 "잘못 열린다"에 해당.

**최종 결정 (사용자 확정):** **지금 바로 슬래시 명령을 함께 만든다.**

- 발동 규칙 한 줄과 슬래시 명령을 **병행**한다
- 슬래시 명령은 자동 판정이 실패해도 확실히 부를 수 있는 두 번째 문이며, 검증에서 지적된 두 위험(경쟁에서 짐, 잘못 열림) 모두에 걸리지 않는다
- 국면 2에 기록해 둔 "관측 후 확장" 조건을 검증이 앞당겨 충족시킨 것으로 본다
- 슬래시 명령 추가 후 Claude Code 재시작 안내가 필요하다 (`tasks/lessons.md` 2026-03-26 교훈)

**합의 (셋 모두, 서로를 못 본 상태에서)**

- 위험은 "발동" 한 곳에 몰려 있다
- 구현 비용 자체는 낮고, 진짜 비용은 규범 충돌을 정리하는 문장 작업에 있다
- 지금 완성 판정 기준으로는 이 설계가 틀렸다는 것을 알아낼 수 없다 — 반증 가능한 관측 지표가 필요하다

**미합의**

- 없음 (등급이 갈린 두 지점은 감사에서 포착 범위 차이로 판정됐고, 양쪽 근거를 모두 채택했다)

**전제 반박 요지 (세 전문가 공통)**
