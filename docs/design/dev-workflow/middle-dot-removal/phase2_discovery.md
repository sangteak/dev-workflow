## 국면 2에서 새로 발견된 미정의 영역과 결정

### A. 이름을 부르는 줄의 면제 방식 — 사용자 결정
- 줄에서 고정 문구 `가운뎃점(·)`을 지운 뒤 남는 ·를 센다. 면제 목록도 인라인 면제 주석도 없다. 이름 줄에 나열 ·가 섞이면 잡힌다
- 걷기는 제외 목록이 아니라 포함 목록이다. `git grep -I -c --untracked $'\xc2\xb7' -- skills commands hooks README.md CLAUDE.md tasks/lessons.md tests scripts docs/design ':(exclude)**/phase[0-9]_*.md' ':(exclude)**/_archive/**' ':(exclude)**/evidence/**'` 모양. mcp/는 범위 밖(코드가 ·를 문자로 쓴다)
- 옛 헤더 모양의 잔존 패턴은 두지 않는다(전역 0건 검사가 이미 잡음). 대신 새 헤더 모양의 도착 검사를 decision-flow 50행, context-handling 84행, bootstrap 폴백에 건다(칸 삭제로 통과하는 것을 막음)
- 치환 워커 명령에 "문구 `가운뎃점(·)`은 건드리지 않는다"를 박는다

### B. 스윕 워커의 조작 범위 — 페르소나 합의
- 허용 연산 셋: · 를 쉼표나 와/과로 바꾸기, 층이 있으면 `- ` 불릿으로 줄 나누기, 항목 안 쉼표를 피하는 어순 재배치. 낱말을 더하거나 빼거나 바꾸지 않는다
- 도메인 문서(SSOT)도 같다. 층이 있는 줄은 어순 재배치보다 불릿을 먼저 고른다(정책 문장의 항목 수 보존)
- 설계에서 「치환 고정표」를 미리 정해 워커에게 준다 — 절 이름(「결정·질문 구조 규범」→「결정과 질문 구조 규범」, 「공통 형식·언어」→「공통 형식과 언어」), 헤딩 다섯, 한 줄 표시(헤더 B, 첫 질문 안내줄, 검증 결과 줄, 검증 태그 범례 489행), HANDOFF 세 줄(context-handling 84, 86, 88행), 꼬리표 규칙(360행). 파일별 워커가 제각각 정하지 않게 한다
- 리뷰 앞에 기계 대조: hunk마다 ·, 쉼표, 와, 과, 공백, 불릿 접두, 마침표, 줄표를 지운 글자 다중집합이 같은지 비교. 같으면 통과, 다르면 리뷰어가 눈으로 본다
- 리뷰어 항목에 "쉼표만으로 끝난 나열이 있는가"를 넣는다(마지막은 와/과)
- 모델 배정: 층 판정이 있는 파일은 researcher(sonnet), 단순 치환은 grunt(haiku). 디스패치에 예시 문구를 넣지 않는다(lessons.md 교훈)

### C. 옛 인용을 옮기는 모양 — 페르소나 합의
- 새 evidence/ 폴더는 만들지 않는다. 인용 줄 실물은 reask-cases-all.md 17줄(이미 면제), reask-reassembly.md 1줄(136행), code-name-lookup.md 2줄(26행 요약, 124행 되돌린 화면)뿐
- 옛 화면 원문(가)은 기존 evidence 파일의 행 번호 참조로 바꾸고, 참조 줄에 화면 조각을 0자로 둔다(치환하면 거짓 증거)
- 되돌린 화면(다), 요약 줄, ux-consistency 217행 같은 살아 있는 참조는 새 모양으로 고쳐 쓴다(사례 재현 절이 "통과의 본"을 잃지 않게)

### D. 실사용 확인의 판정 방식 — 사용자 결정
- 세션 transcript(`~/.claude/projects/<프로젝트>/*.jsonl`)의 `type=assistant` 줄에서 `message.content[].type=="text"`만 뽑아, A 방식으로 문구를 지우고 ·를 센다. 스크립트는 tests/에 둔다(다음 릴리스도 씀)
- 유발 목록 다섯: 국면 0 화면과 첫 결정 박스(헤더와 결과 줄), 국면 1 첫 질문(안내줄), 블라인드 라운드 발언 나열(워커 펜스 사본을 보는 유일한 자리), `/dev-workflow:save`가 쓴 HANDOFF.md, 마무리 요약. 되물음 접미는 일부러 한 번 되물어 별도 확인
- 도착 조건: 다섯 자리 각각에서 쉼표나 불릿 나열이 1건 이상 관측되어야 0건이 의미를 갖는다
- 위반 줄은 원문과 출처(옛 HANDOFF 복구 화면인지, 새로 쓴 화면인지)를 적어 규범 실패와 복구 실패를 가른다
- 기록은 이 문서 9절 표 하나에 항목별 귀속 릴리스(1.26.0 닫힌 질문 번호, 1.26.1 이름표 개행, 1.27.0 0번 렌더와 풀이 병기와 접미 붙음, 1.27.1 고지 한 줄과 원문+풀이와 번역어 0회, 1.27.2 접미 구분자와 헤더 쉼표와 · 0개)로 적고, 앞선 네 문서의 "실사용 미완료" 행은 그 표를 가리키는 한 줄로 닫는다
