# middle-dot-removal 설계 문서

> 한 줄 요약: 화면 문장이 가운뎃점(·)으로 나열을 잇는 문체를 없앤다 — 규범 한 줄이 아니라 모델이 읽는 글 전체의 스윕과 상시 잔존 검사로.

## 1. 배경과 동기

- 사용자 화면에 "스테이징 대상은 스크립트, 시나리오, 설계 문서 세 파일이고"를 점으로 이은 문장이 나왔고, 사용자는 읽기 불편하다고 했다. 항목에 띄어쓰기가 있으면 점의 경계가 안 보인다. 사용자의 결론은 "중간 점을 쓸 이유가 전혀 없다"이다
- 원인은 흉내다. 규범에 "병렬 나열은 불릿으로 쓴다" 줄이 이미 있지만, 그 규범 문서 자체가 점으로 나열해 모델이 그 문체를 따라 쓴다. 실측: 추적 파일에서 점 733개(docs 제외), 스윕 범위 안 43파일 626줄 1,418개. 세션마다 주입되는 bootstrap에만 49개
- 앞선 기능들(question-numbering 1.26.0, decision-label-linebreak 1.26.1, reask-reassembly 1.27.0, code-name-lookup 1.27.1)이 언어 규범을 한 줄씩 고쳐 왔고, 이번은 그 문서들의 문체 자체를 고친다

## 2. 목표와 비목표

### 목표
- GOAL-001: 모델이 읽는 모든 글과 docs/design의 도메인 문서와 설계 문서에서 가운뎃점(·) 나열을 없앤다. 남는 자리는 규칙에서 이름을 부르는 문구 "가운뎃점(·)"뿐이다
- GOAL-002: 문장 안 나열의 새 규칙을 언어 규범에 넣고, 재발을 상시 검사로 막는다
- GOAL-003: 실사용 한 바퀴에서 화면에 점이 0개임을 기계로 세어 통과를 선언한다

### 비목표
- svg 그림과 mcp/ 소스 주석 — 모델이 읽지 않는다
- phase 파일, `_archive/`, `evidence/` — 불변 규칙, 스캔 제외, 채집 원문
- 다른 문장부호 규범(대시, 슬래시, 절 기호)을 이번에 손대는 일 — 단 첫 질문 안내줄의 슬래시는 한 줄 표시 셋에 들어 치환 고정표로 다룬다
- 화면을 내보낸 뒤 다시 읽어 고치는 재생성 루프나 훅 신설 — 억제이지 보장이 아니다
- 도메인 머지(merge-to-domain)와 원격 푸시 — 앞선 미푸시 릴리스와 함께 뒤에 한다

## 3. 확정된 요구사항

### 규범
- REQ-001: 언어 규범 펜스(decision-flow 3부)에 가운뎃점(·) 금지 줄 하나와 올바른 문장 예시 하나를 병기한다. 이 펜스는 워커 프롬프트 열한 곳에 실행 시점에 복사되므로 예시가 워커의 본이 된다. 이름 문구의 철자는 "가운뎃점(·)" 한 모양으로 고정한다 — 우선순위: HIGH
- REQ-002: 규칙 문장. 문장 안 나열은 쉼표와 "와/과"로 잇고 "와/과"는 마지막 한 번만. "또는" 뜻이면 "나/이나". 층이 있으면(항목이 쉼표나 줄표를 품거나 나열이 두 층) 줄을 나눠 불릿으로. 표 칸, 커밋 제목과 한 줄 표시처럼 줄을 못 나누는 자리는 쉼표. 항목 안에 쉼표가 들면 어순을 바꿔 없앤다. "그리고"는 층 나누기에 쓰지 않는다. 따옴표 항목은 층이 아니다(따옴표가 경계를 만든다). 술어(동사구) 나열은 쉼표로만 잇고 "와/과"를 붙이지 않는다(요약 자리 넷과 표 칸) — 우선순위: HIGH
- REQ-003: 되물음 꼬리표 규칙(decision-flow 360행)을 "앞은 쉼표, 마지막만 와/과"로 바꾼다. 둘이면 `(다시 씀: 왜 문제인지와 고르면 어떻게 되는지)`, 셋이면 `(다시 씀: 낱말 풀이, 왜 문제인지와 고르면 어떻게 되는지)`. 실사용 표에서 접미 항목은 1.27.0(접미가 붙는가)과 1.27.2(구분자 모양) 공동 귀속으로 표시한다 — 우선순위: HIGH
- REQ-004: 한 줄 표시 셋을 쉼표로 이은 한 줄로 바꾼다. 결정 진행 헤더 `📋 확정 N/M, 진행 중: [결정명], 다시 볼 것 K건`(K=0이면 마지막 칸 생략), 첫 질문 안내줄, 검증 결과 줄 `✅ PASS: N, ⚠️ PARTIAL: N, ❌ FAIL: N`. 이름표 없는 칸(context-handling 116행 코드 이름 목록 절의 자리 줄)은 이름표를 붙인다 — 우선순위: HIGH
- REQ-005: 「내보내기 전 검사」에 여섯째 항목 "가운뎃점(·) 0개"를 더한다. 이미 써 둔 문장을 다시 보는 검사라 별도 호출이나 재생성이 없다. 재서술 지점의 검사 요약(bootstrap, SKILL 폴백)에도 같은 항목을 넣는다 — 우선순위: HIGH
- REQ-006: bootstrap에는 짧은 조각만 둔다. 36행 폴백 한 줄(점 15개, 1,865바이트)은 "폴백:" 한 줄 아래 불릿 묶음으로 풀고 괄호를 없앤다. 8행의 두 층 나열은 21~25행 표를 가리키는 한 줄로 줄인다. 줄 수 상한은 없다 — 우선순위: MEDIUM

### 스윕
- REQ-007: 스윕 범위는 포함 목록이다 — skills, commands, hooks, README.md, CLAUDE.md, tasks/lessons.md, tests, scripts, docs/design. 면제는 경로 셋뿐 — `phase[0-9]_*.md`, `_archive/`, `evidence/`. 구문(펜스, 인용 블록, 백틱) 면제는 두지 않는다. skills 펜스 안 57개는 살아 있는 템플릿이라 검사 대상이다 — 우선순위: HIGH
- REQ-008: 워커의 허용 연산은 셋뿐이다 — 점을 쉼표나 와/과나 나/이나로 바꾸기, 층이 있으면 `- ` 불릿으로 줄 나누기, 항목 안 쉼표를 피하는 어순 재배치. 층 나누기에서 이음말("중 하나", "셋")과 줄표를 머리 줄로 옮기는 것은 허용 연산에 든다. 그 밖에 낱말을 더하거나 빼거나 바꾸지 않는다. 예외는 치환 고정표 자리와 bootstrap 폴백뿐이며 거기서만 "진행 중:" 같은 이름표 낱말 추가를 허용한다 — 우선순위: HIGH
- REQ-009: 도메인 문서(SSOT)의 평문 단락은 불릿으로 내리지 않고 쉼표와 "와/과"로 한 문장을 유지한다(merge-to-domain의 digest가 불릿을 정책 항목으로 세므로). complete feature 문서 넷(code-name-lookup, reask-reassembly, question-numbering, decision-label-linebreak)도 도메인 머지의 digest 입력이라 같다. 스킬 문서와 README는 불릿 허용. 대조 스크립트가 `docs/design/dev-workflow/*.md`와 feature 문서에서 새 `- ` 접두를 불허해 이 규칙을 기계가 본다 — 우선순위: HIGH
- REQ-010: 치환 고정표를 PLAN에서 만들어 워커에게 준다. 항목: 절 이름 둘(새 이름 「결정과 질문 구조 규범」과 「공통 형식과 언어」 — 옛 이름은 두 낱말을 점으로 이은 것, 참조 열다섯 줄), 헤딩 다섯, 한 줄 표시 셋과 검증 태그 범례(489행), HANDOFF 세 줄(context-handling 84, 86, 88행), 꼬리표 규칙(360행), 268행과 429행의 같은 문장, 355~357행 표 칸 셋, bootstrap 36행 괄호 구조, "또는" 자리 아홉(decision-flow 54행, bootstrap 36행 둘, orchestrator SKILL 431행과 435행, grounding.md 26행, context-handling 90행, intake-nudge 27행, brainstorming SKILL 67행, completion-nudge 40행), 첫 질문 안내줄의 슬래시(249행), 살아 있는 참조(code-name-lookup 124행과 128행의 되돌린 화면, ux-consistency 217행). 워커가 제각각 정하지 않게 한다. 고정표는 plan.md와 함께 지워지므로 9절에 "파일:행 → 새 값" 색인으로 남기고 시작 커밋 SHA와 원문 앞 조각을 병기한다 — 우선순위: HIGH
- REQ-011: 설계 문서 안 옛 화면 인용은 기존 evidence 파일의 행 번호 참조로 바꾸고, 참조 줄에는 화면 조각을 0자로 둔다(치환하면 거짓 증거). 새 evidence/ 폴더는 만들지 않는다. 참조 줄은 불릿이 아닌 평문으로 — 우선순위: MEDIUM
- REQ-012: README의 화면 견본(363행, 113행 등)은 전부 새 모양으로. lessons.md는 예외 없이 전부 고친다(점이 든 줄 39개, 옛 화면 인용 없음). 검사 스크립트 넷(test-restatements.sh, check-restatements, sweep, bump-version)과 test-completion-nudge.sh의 주석과 고정 문구도 고친다. scripts/sweep은 주석만 고치고 범위는 손대지 않는다 — 우선순위: MEDIUM
- REQ-013: 워커 규칙. Edit만 쓴다(줄 끝이 CRLF와 LF로 섞여 있어 Write는 줄 끝을 바꾼다). 층 나누기가 없는 파일에서는 `git diff --stat` 줄 수가 점이 든 줄 수와 맞는지 본다(층 파일은 줄이 늘어 이 검사를 걸지 않는다). 디스패치에 예시 문구를 넣지 않고 고정표와 규칙 문장만 준다. 배정은 파일 단위 — 도메인 문서 일곱과 feature 문서 넷과 층 판정 파일(decision-flow, orchestrator SKILL, bootstrap, brainstorming SKILL, merge-to-domain SKILL, lessons, README)은 researcher(sonnet), 점이 1~6개인 파일(스크립트, 훅, commands, 작은 스킬)만 grunt(haiku) — 우선순위: HIGH
- REQ-014: 재서술 지점 열둘 갱신과 도착 문면 확인은 기존 관행대로. 스윕 커밋은 도메인 머지와 같은 세션에 섞지 않는다 — 우선순위: MEDIUM

### 검사
- REQ-015: `tests/hooks/test-restatements.sh`에 잔존 헬퍼를 새로 둔다(기존 arrival과 residue는 건드리지 않는다). 두 단계 — `git grep -nI --untracked` 포함 목록과 제외 셋으로 줄을 뽑고, sed로 문구 "가운뎃점(·)"을 지운 뒤 남는 점을 세어 파일과 행을 보고한다. 점 패턴과 sed 패턴은 바이트 이스케이프 변수(dot)로 조립해 스크립트 자신이 0건을 유지한다. 판정은 0건 — 우선순위: HIGH
- REQ-016: 도착 검사 셋. 규범 줄의 문구 "가운뎃점(·)"이 decision-flow와 bootstrap에 1건 이상. 새 헤더 모양이 decision-flow 50행, context-handling 84행, bootstrap 폴백에 도착(패턴은 파일별 원문에 맞춤 — bootstrap은 `확정 N/M,`까지). 검사 여섯째 항목 조각이 bootstrap과 SKILL 폴백에 도착. 새 절 이름 둘이 decision-flow와 orchestrator SKILL에 도착. 꼬리표 새 모양 예시가 decision-flow에 도착. bootstrap 헤더 패턴은 고정표의 "폴백 헤더에 진행 중: 칸 추가" 항목과 한 쌍이다. 기존 도착 조각 넷(식별자는 즉석 풀이, 풀이 없는 것, 다시 씀: , 코드 자리에서 1건 이상)이 불릿 경계에서 끊기지 않았는지가 리뷰 항목이다. 옛 헤더 잔존 패턴은 두지 않는다(전역 0건 검사가 이미 잡는다) — 우선순위: HIGH
- REQ-017: 대조 스크립트를 node로 새로 둔다(jq 없음, mcp가 이미 Node 18+를 요구). `git diff -U0`의 hunk마다 CR을 벗기고 방향 있는 차이를 본다 — 옛 쪽에만 남는 글자는 점뿐, 새 쪽에만 남는 글자는 쉼표, 공백, 개행, 불릿 접두, 와, 과, 나, 이나뿐, 새로 생긴 조사 수는 지운 점 수 이하. 받침 검사 한 줄(앞 글자가 한글일 때만 — 코드에서 0xAC00을 뺀 값을 28로 나눈 나머지가 0이면 "와"). 통과 hunk 건너뛰기는 평탄 치환 hunk에만 성립한다. 층 나누기 hunk와 어순 재배치 hunk와 고정표 자리 hunk와 실패 hunk는 필독 표시 — 우선순위: HIGH
- REQ-018: 태스크 리뷰어 항목에 "쉼표만으로 끝난 나열이 있는가(마지막은 와/과)", "와/과는 마지막 한 번인가", "받침이 맞는가", "낱말이 더해지거나 빠졌는가(고정표 자리 제외)"를 넣는다. 자리 예외를 병기한다 — 한 줄 표시와 표 칸은 쉼표만이 정상이라 "쉼표만 나열" 항목에 걸지 않는다 — 우선순위: MEDIUM

## 4. 설계 개요

- **한 줄 규칙과 본.** 정본은 decision-flow 3부 「언어 규범」 펜스. 금지 줄 하나와 바른 예시 하나가 들어가고, 펜스 전문이 워커 프롬프트 열한 곳에 실행 시점에 복사되어 워커의 본이 된다. bootstrap에는 조각만
- **흉내 원천 제거.** 포함 목록 아홉 경로에서 점 1,418개를 허용 연산 셋으로 치환한다. 절 이름과 한 줄 표시처럼 여러 파일이 같은 모양을 가져야 하는 자리는 치환 고정표가 값을 정한다. 도메인 문서 평문은 불릿으로 내리지 않는다
- **뜻 보존 대조.** hunk마다 방향 있는 글자 차이를 node 스크립트가 세고, 통과 hunk는 리뷰어가 건너뛴다. 사람 눈은 실패 hunk와 재배치 hunk와 "와/과 마지막 한 번"만 본다
- **상시 검사.** 잔존 헬퍼(문구 제거 후 0건)와 도착 검사 셋이 릴리스마다 돈다. 이름 문구가 검사의 유일한 예외라 목록이 없다
- **실사용 판정.** transcript 스크립트가 메인과 워커 발언을 같이 세어 0줄과 도착 조건으로 판정한다

## 7. 제약조건과 가정

- 가운뎃점(·)은 U+00B7 2바이트라 이 환경 grep이 잡는다. 이모지가 든 패턴만 LC_ALL=C가 필요하다
- 줄 끝이 섞여 있다(decision-flow, lessons, README는 CRLF, ux-consistency는 LF, core.autocrlf=true). 워커는 Edit만 쓴다
- jq가 없다. node 24와 python 3.13이 있다. 새 스크립트는 node로
- 워커 발언은 주 transcript에 tool_result로만 들어오고 원문은 세션 폴더의 `subagents/agent-*.jsonl`에 쌓인다
- 가정: 화면의 점은 흉내다 — 모델이 읽는 글에서 없애면 화면에서 사라진다. 저장소 밖 입력(소비 프로젝트의 옛 HANDOFF.md, 붙여 넣은 원문, 사전 지식)은 남으므로 억제이지 보장이 아니다. 실사용 위반 줄의 출처 기록이 규범 실패와 복구 실패를 가르는 마지막 안전망이다
- 가정: 실사용 한 바퀴는 앞선 미확인 릴리스 넷(1.26.0, 1.26.1, 1.27.0, 1.27.1)의 확인과 같은 바퀴다
- 이 설계 문서 본문에는 이름 문구 밖에서 점을 쓰지 않는다. HANDOFF는 마무리에 지워진다

## 8. 기술 가이드라인

- 검사 패턴과 sed 패턴은 바이트 이스케이프(dot 변수). 포함 목록 pathspec: `-- skills commands hooks README.md CLAUDE.md tasks/lessons.md tests scripts docs/design ':(exclude)**/phase[0-9]_*.md' ':(exclude)**/_archive/**' ':(exclude)**/evidence/**'`
- 워커 디스패치는 규칙 문장 셋(허용 연산, 낱말 불변, 고정표 값 그대로)과 고정표만 준다. 예시 문구를 넣지 않는다(lessons.md 교훈)
- 층 판정 파일은 디스패치 전에 스크립트로 가른다 — 한 줄 안에서 점 사이에 쉼표나 줄표가 있으면 층 후보
- 도메인 머지는 스윕 커밋 뒤, 다른 세션에서
- transcript 스크립트와 대조 스크립트는 `tests/hooks/test-*.sh` 이름을 피한다(run-all이 집는다)
- 다음 스윕 워커에게는 위 「구현 중 굳은 규칙」 여섯을 규칙 문장과 함께 준다 — 특히 로마자 뒤 받침과 백틱 나열은 규범 줄에 없는 저장소 문서용 규칙이다
- 헤더 도착 패턴은 파일별 원문에 맞춘다. 기존 도착 조각('풀이 없는 것', '다시 씀: ', '코드 자리에서 1건 이상')을 불릿 경계에서 끊지 않는다

### 일탈

1. **규범 줄 자체가 규칙을 어겼다** — 계획의 「새 규범 문면」이 "표 칸과 커밋 제목과 한 줄 표시"로 "와/과"를 두 번 썼고 정본과 REQ-002에 그대로 들어갔다. 최종 리뷰가 잡아 "표 칸, 커밋 제목과 한 줄 표시"로 고쳤다. 계획이 낸 본이 워커 열한 곳에 실리는 자리라 본의 결함이 열한 배가 된다
